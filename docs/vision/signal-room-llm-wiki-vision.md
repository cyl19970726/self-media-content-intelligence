# Signal Room Vision：从内容分析工作台到持续进化的内容知识系统

Status: **Vision Draft for Owner Confirmation**  
Scope: **长期产品愿景；不绑定单一版本、页面或技术实现**  
Date: **2026-08-27**

## 1. Vision

Signal Room 不是一个把视频和博主分析成报告的工具，也不是一个自动生成创作建议的聊天助手。

Signal Room 要构建的是一个持续进化的内容知识系统：

> **由单帖证据、博主模式、跨博主机制和自身创作实验共同维护的内容知识网络。LLM 负责从研究结果中提出、连接和更新知识；每条知识必须保留适用条件、支持证据、反例、未知边界与版本，并最终服务于可追踪、可验证的创作决策。**

这个系统最终要回答的不是笼统的“什么内容会火”，而是：

> 谁，在什么平台，面对什么受众和问题，使用了什么选题、承诺、结构、证据、画面与表达，在什么条件下产生了什么可观察表现；其中哪些只是个案，哪些形成了局部模式，哪些可能跨博主复用，以及这些认知在我们自己的创作中是否经受了验证。

我们的长期愿景是：

> **让每一次内容研究都成为下一次创作可以站上去的认知基础，让每一次真实创作又成为修正这套认知的新证据。工作台不会只是越来越多的报告，而会越用越理解内容，同时始终知道自己为什么这样判断。**

## 2. 我们引用的 LLM Wiki 概念

### 2.1 概念来源

本 Vision 明确引用 Andrej Karpathy 在 2026 年 4 月发布的 [LLM Wiki idea file](https://gist.github.com/karpathy/442a6bf555914893e9891c11519de94f)。Karpathy 将它定义为一种使用 LLM 构建个人知识库的模式，而不是一个固定产品或特定技术栈。

它针对传统文档问答和 RAG 的一个根本问题：模型通常在每次提问时重新检索原始文档、重新拼接碎片、重新形成答案，先前完成的综合、比较和判断没有成为可以持续复用的资产。

LLM Wiki 的核心转换是：

```text
传统 RAG
原始资料 → 每次提问时重新检索和综合 → 一次性答案

LLM Wiki
原始资料 → LLM 持续编译和维护 Wiki → 基于已有知识继续研究
```

Karpathy 的原始模式包含三个层次：

1. **Raw sources**：人工选择、保持不可变的原始资料，是事实来源；
2. **Wiki**：由 LLM 编写和维护、彼此链接的持久知识页面；
3. **Schema**：规定 LLM 如何导入、组织、查询和维护 Wiki 的行为合同。

它包含三个主要操作：

- **Ingest**：加入新来源，更新摘要、实体、概念、索引、交叉引用和冲突；
- **Query**：基于已积累的 Wiki 回答问题，并把有价值的新综合写回；
- **Lint**：检查矛盾、陈旧主张、孤立页面、缺失引用和知识缺口。

其第一性原理是：

> **不要让模型每次重新思考已经思考过的问题；把已经形成的理解保存为可追溯、可修订、可继续生长的持久知识。**

### 2.2 我们继承什么

Signal Room 完整继承 LLM Wiki 的五个核心思想：

1. **知识必须积累**：研究结果不能只停留在一次报告或聊天记录里；
2. **知识需要编译**：原始资料需要被组织成概念、实体、关系、冲突和综合判断；
3. **知识必须持久**：一次好的分析要成为后续研究和创作可以复用的资产；
4. **LLM 负责繁重维护**：摘要、链接、更新、冲突检查和索引不应依赖人持续手工完成；
5. **人负责策源和判断**：人选择资料、提出问题、决定重点并作最终判断。

### 2.3 我们为什么不能直接照搬

Karpathy 的原始 LLM Wiki 面向个人研究，主要载体是由 LLM 维护的 Markdown。Signal Room 面向内容研究、创作决策和发布验证，存在更严格的要求：

- 一条高点赞帖子不能直接成为“有效规律”；
- 公开互动不能证明曝光、完播、转化或因果；
- 同一模式可能只对某个博主、题材、形式或时间窗口成立；
- 支持证据和反例必须同时保留；
- 创作时必须知道引用了知识的哪个版本；
- 发布结果必须回到系统，但不能绕过研究闸门直接改写规律；
- 原始证据、模型观察、规律知识和行动决策必须具有不同权限。

因此，Signal Room 不是实现一个普通的 Markdown Wiki，而是将 LLM Wiki 扩展成一个**证据化、版本化、有知识晋升闸门、能够连接创作与真实反馈的内容智能系统**。

### 2.4 从三层扩展为五层

我们将 Karpathy 的三层模式扩展为适合内容智能的五层：

```text
Karpathy LLM Wiki                Signal Room Content Intelligence Wiki

Raw sources                     ① 原始证据层
                                视频、帖子、评论、指标、字幕、画面

Wiki                            ② 研究档案层
                                单帖还原、博主模型、多博主比较

Wiki                            ③ 内容知识层
                                观察、概念、条件、反例、关系、版本

                                ④ 创作决策层
                                选题、假设、脚本、素材、平台版本

                                ⑤ 实践验证层
                                发布结果、反馈、复盘、知识回流

Schema                          贯穿五层的合同、权限、闸门和 lineage
```

其中第③层是狭义的 Wiki，第①至⑤层共同组成完整的 LLM Wiki 知识循环。

这也明确回答一个容易混淆的问题：

> 单帖和单博主分析是在构建 Wiki，但它们主要生产知识原料与局部模式；真正的知识 Wiki 负责把这些产物编译成能够跨来源复用、被新证据修正、并被创作决策引用的知识。

## 3. 北极星结果

系统的长期价值不以“生成了多少报告”衡量，而以以下结果衡量：

1. 每完成一次研究，系统对内容世界的理解是否变得更准确，而不是只增加一份孤立报告。
2. 每次创作决策能否说明依据了哪些知识、使用的是哪个版本、主动测试了什么假设。
3. 每次发布和复盘能否反过来支持、限定或反驳已有知识。
4. 新证据出现后，旧结论能否被修正、降级或失效，而不是永久残留为“历史真理”。
5. 用户能否从任何重要判断返回原帖、视频时间码、画面、评论、指标与分析版本。

最终形成的复利闭环是：

```text
原始证据
  → 单帖结构化观察
  → 单博主局部模式
  → 跨博主条件性机制
  → 自己的创作假设与决策
  → 发布结果与真实反馈
  → 支持 / 限定 / 反驳原有知识
```

## 4. 什么是知识

### 4.1 知识不是摘要

一段内容总结、一个标签、一段漂亮的模型分析、一次高点赞案例，都不能单独成为可复用知识。

在 Signal Room 中，一条合格知识至少包含：

```text
一个可判定的主张
+ 明确的适用对象与范围
+ 成立条件
+ 支持证据
+ 限定或反对证据
+ 替代解释与未知边界
+ 当前状态和置信度
+ 不可变版本历史
```

“结果前置能够提升收藏”不是合格知识。

以下表达才接近合格知识：

> 在当前观察到的教程与改造型内容中，当最终结果具有明显视觉差异、且用户能快速识别其价值时，结果前置经常与更高的收藏表现同时出现。当前证据来自三个博主的九条视频，但缺少曝光、完播和受控实验数据，因此不能确认其独立因果作用。

### 4.2 知识必须能够变化

知识不是静态文章，而是一个能够被新证据影响的版本化判断。新证据可以：

- `confirm`：在既有范围内增加支持；
- `qualify`：缩小适用条件或修正定义；
- `contradict`：构成当前主张范围内的反例；
- `invalidate`：证明证据、映射或研究过程本身不可靠；
- `promote`：在满足证据门槛后扩大适用范围；
- `demote`：证据不再支撑原范围时缩小适用范围；
- `retire`：不再作为当前知识使用，但保留历史。

支持证据增加不自动意味着扩大范围；出现反例也不自动意味着删除概念。

## 5. 五类核心知识对象

整个系统由五类彼此连接、职责不同的对象组成。

### 5.1 帖子证据页：这条内容具体做了什么

单帖是最小研究对象和主要证据来源。它应保存：

- 来源、作者、发布时间、公开指标与采集状态；
- 完整内容还原、逐字稿、知识单元、案例、步骤、限制和 CTA；
- 目标受众、用户问题与价值交付；
- 开场、承诺、冲突、发展、证明、兑现和结尾；
- 证明方式、信任来源与主张边界；
- 画面、字幕、镜头、剪辑和声音如何承载意义；
- 相对博主基线与题材基线的表现；
- 评论区实际表达的需求、质疑和执行反馈；
- 事实、观察、作者主张、系统推断和未知的明确区分。

单帖页产生的是一组证据化观察，不直接产生“通用规律”。

### 5.2 博主实体页：这个人稳定地会什么

单博主分析从多个帖子中形成局部内容模型，包括：

- 服务对象、受众问题、账号定位与信任来源；
- 实用、认知、情绪、身份、社交和决策价值；
- 稳定栏目、选题组合、内容产品与发布节奏；
- 重复出现的编导手法、证明方式和视觉语言；
- High / Base / Low 之间的差异与共同项；
- 高表现关联模式、低表现失败模式、反例和混杂因素；
- 生命周期、内容演化和当前未知项。

博主页产生的是“对该博主、该样本和该时间窗口成立的局部模式”，不能自动泛化为平台规律。

### 5.3 机制概念页：什么规律可能跨个案复用

机制概念是知识网络的核心复利单元，包括但不限于：

- 内容机制 `content_mechanism`；
- 编导手法 `directing_device`；
- 视觉语法 `visual_grammar`；
- 证明方式 `proof_mode`；
- 失败模式 `failure_mode`；
- 价值模式 `value_mode`；
- 成立条件 `condition`。

每张概念页必须展示：

1. 定义和排除边界；
2. 当前范围、状态和版本；
3. 成立条件与不适用条件；
4. 支持、限定和反驳证据；
5. 博主、视频、层级和时间窗口分母；
6. 替代解释与因果边界；
7. 版本变化和决策理由；
8. 相关概念与语义关系；
9. 当前缺口和下一步需要的证据。

### 5.4 创作决策页：我们为什么这样做

创作决策将研究知识转化为一次有边界的实践选择。它必须记录：

- 内容目标、目标受众和具体场景；
- 引用的概念及其固定 revision；
- 参考的帖子和博主证据；
- 本次采用、改造或拒绝了什么；
- 主动测试的创作假设；
- 预期可观察信号和不可判断项；
- 脚本、画面、平台版本与最终发布 revision。

研究知识不会自动变成创作命令。创作区拥有独立授权，负责结合我们的定位、能力、资源和目标作出决定。

### 5.5 实验复盘页：应用以后发生了什么

发布结果和真实反馈形成自己的实践证据，包括：

- 冻结的创作版本和发布时间；
- 可获得的曝光、互动、收藏、评论、分享、留存和转化数据；
- 与自身基线和可比较内容的差异；
- 评论、用户行为和执行反馈；
- 实际执行与原计划的偏差；
- 对创作假设的支持、限定或反驳；
- 可否进入研究知识的独立裁决结果。

一次发布结果不能直接覆盖研究概念；它先形成观察，再经过证据与裁决闸门。

## 6. 知识成熟度阶梯

系统必须让用户随时知道一条判断处于哪个层级：

| 层级 | 含义 | 可否直接泛化 |
| --- | --- | --- |
| 原始事实 | 原文、画面、指标、评论等可核验证据 | 否 |
| 单帖观察 | 对一条内容的证据化判断 | 否 |
| 博主级模式 | 对单一博主、样本和窗口成立的重复模式 | 否 |
| 条件性规律 | 在多个博主中、明确条件下重复出现 | 仅限条件内 |
| 赛道级规律 | 经可比较样本和反例检查后形成的较广判断 | 仍非因果定律 |
| 创作假设 | 结合我们的目标后准备实践的判断 | 待验证 |
| 自有验证结果 | 我们执行后的实际结果 | 仅限实验边界 |

系统不得通过语气或页面位置让较低层级的判断伪装成较高层级知识。

## 7. 核心语义链接

LLM Wiki 的价值不来自普通页面双链，而来自可计算的语义关系。

```text
帖子 ──支持 / 限定 / 反驳──→ 概念
帖子 ──属于──→ 博主
帖子 ──采用──→ 编导手法 / 视觉语法 / 证明方式

博主 ──稳定使用──→ 概念
博主 ──服务──→ 受众问题 / 价值模式
博主 ──出现──→ 失败模式

概念 ──依赖──→ 条件
概念 ──组合──→ 另一概念
概念 ──冲突──→ 另一概念
概念 ──更具体 / 更一般──→ 另一概念

创作决策 ──引用──→ 概念 revision
创作决策 ──参考──→ 帖子 / 博主
发布结果 ──验证──→ 创作假设
复盘观察 ──支持 / 限定 / 反驳──→ 概念
```

每条关系必须保留创建来源、作用范围和版本；模型推断的关系在通过裁决前只能是候选关系。

## 8. LLM、人和系统闸门的分工

### 8.1 LLM 是知识编译器，不是真理所有者

LLM 可以自动：

- 还原和结构化单帖内容；
- 提取证据化候选观察；
- 将观察匹配到已有概念；
- 提议新概念、别名和语义关系；
- 补充支持、限定和反驳证据；
- 更新摘要、索引和相关页面；
- 检查冲突、陈旧结论、孤立页面和证据缺口；
- 提议下一轮值得研究的问题。

LLM 不得自动：

- 把相关性改写为因果性；
- 把单条高表现内容晋升为通用规律；
- 删除原始证据、旧 revision 或反例；
- 把不完整来源标记为确定事实；
- 把模型推断直接变成创作命令；
- 把一次发布结果直接写成赛道规律。

### 8.2 人负责方向和最终判断

人负责：

- 选择研究对象和研究问题；
- 决定哪些知识值得重点维护；
- 审核重大概念合并、拆分和范围变化；
- 结合自身目标作出创作决策；
- 决定风险、资源、品牌与商业边界；
- 对高影响知识晋升和发布行为作最终授权。

### 8.3 系统闸门负责一致性

确定性规则负责：

- 来源完整性和证据可解析性；
- 分母、样本、范围和版本校验；
- 晋升、降级、失效和回归门槛；
- 角色权限和盲测输入隔离；
- 写入幂等性、事件历史和依赖失效传播。

## 9. 产品表面与职责边界

| 产品区域 | 核心问题 | 主要对象 |
| --- | --- | --- |
| 链接分析 | 这条内容完整表达了什么、如何构建、证据在哪里 | 帖子证据页 |
| 博主研究 | 这个博主经营着怎样的内容系统 | 博主实体页、局部模式 |
| 多博主研究 | 哪些模式共同、不同、条件性或异常 | 比较结论、候选概念 |
| 内容知识 | 系统当前真正知道什么、依据什么、还缺什么 | 机制概念页、关系、revision |
| 创作发布 | 基于当前知识和自身目标，这次决定怎么做 | 创作决策、内容包、平台版本 |
| 迭代验证 | 实际结果是否支持原假设，系统是否应该更新 | 实验复盘、裁决、回归 |

研究表面描述外部内容，不输出“我们应该复制什么”。内容知识表面维护可复用判断，不直接生成未授权的发布动作。创作表面可以引用知识，但必须保留独立决策过程。

## 10. 真相源和可读投影

Signal Room 不直接采用“Markdown 文件即全部真相”的实现。

### 机器真相层

- 原始证据和不可变 artifact；
- SQLite 持久账本；
- 版本化 JSON/schema；
- append-only event；
- evidence reference、hash 和 lineage；
- ResearchConcept、Observation、Revision 和决策对象。

### 人类阅读层

- 工作台知识页面；
- 搜索、筛选和关系视图；
- 自动生成的 Markdown / Obsidian / Notion 投影；
- 可分享或导出的研究与知识快照。

阅读投影不能静默覆盖机器真相。人工编辑阅读页时，系统应产生变更提议，校验后创建新 revision。

## 11. 非目标

本系统不承诺：

- 从公开点赞推导确定的流量因果；
- 生成一个永远正确的“爆款公式库”；
- 用知识图谱替代原始视频、报告或人的判断；
- 自动复制其他博主风格；
- 让 LLM 在没有证据和授权时自主决定并发布内容；
- 为了让 Wiki 看起来完整而补造缺失数据；
- 把所有聊天回答、标签或分析段落永久保存为知识。

## 12. 不可退让的产品原则

1. **证据与理解分离**：模型可以修改理解，不能篡改证据。
2. **观察与规律分离**：个案观察不会因为表达有说服力就成为规律。
3. **研究与创作分离**：外部规律不会自动成为我们的行动命令。
4. **相关与因果分离**：公开表现支持关联判断，不默认支持因果判断。
5. **支持与反例并存**：知识页必须让反例与支持证据同样可见。
6. **范围由证据挣得**：知识只能在证据支持的对象、条件和时间窗口内成立。
7. **每次决策可回放**：创作必须固定所依据的知识和内容 revision。
8. **每次结果可回流**：发布不是流程终点，而是新证据的开始。
9. **失败历史不可擦除**：修复产生新版本，不覆盖旧失败。
10. **没有晋升也是有效结果**：一次高质量研究可以只增加边界和未知，而不产生新规律。
