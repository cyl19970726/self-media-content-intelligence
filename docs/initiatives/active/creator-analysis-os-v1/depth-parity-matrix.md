# 深度迁移验收矩阵

这组检查的目标不是验证 JSON “长得像”报告，而是验证旧研究资产迁移后仍能支持真实判断。源数据真实缺失时允许 `partial`，但必须写清缺失通道、影响和失败闸门；空数组、`unknown`、兼容说明或套话不能代替研究结果。

## 单视频验收

每位博主固定一条代表视频作为深度冒烟样本：

- AI红发魔女：`6801c0750000000007037156`
- 张咋啦：`6a31edc300000000200387f4`
- 人类最强编导：`6a2fcd940000000007021a9f`

每条至少必须具有：

1. 内容还原：明确 thesis、可独立阅读的 article、多个知识单元；
2. 编导逻辑：观众认知前后变化，以及至少两个实际叙事阶段；
3. 画面与剪辑：画幅、构图和具体观察，不能只写“待恢复结构化指标”；
4. 证据：逐字稿、稀疏帧、密集帧、未知/冲突/未检查通道；
5. 部分证据规则：允许 `partial`，但必须披露为什么不能 ready。`partial` 不是空内容的通行证。

## 可执行入口

```bash
npx vitest run src/server/creator-depth-parity.test.ts
```

失败项应被当作迁移待办。只有这组检查通过，才说明工作台至少恢复了既有研究的判断深度；schema 校验通过不代表深度验收通过。
