# Wave 3：让研究成果真正进入 Knowledge Wiki

## 目标

Knowledge 不再只是“报告的另一个展示页”，而是经过人工裁决、可追溯、可撤销的判断库。

每份已经完成的单帖、单博主和多博主研究，都必须得到一个明确结果：

- **进入 Wiki**：证据和晋升闸门都通过。
- **保留在研究层**：结论有价值，但只适用于当前样本。
- **等待证据**：方向可能成立，但缺深度重建、独立评估或足够样本。
- **拒绝**：结论重复、不可证伪、证据错误或不值得保留。

## 必须满足

1. 新研究完成后先生成“知识贡献提案”，不得直接写入正式 Knowledge。
2. 提案包含冻结的分析版本、输入指纹、候选概念、证据引用、拟晋升范围和闸门理由。
3. 操作者明确选择进入 Wiki、保留、等待或拒绝后，系统才记录最终结果。
4. 只有“进入 Wiki”会调用正式编译器；另外三种结果不能产生正式概念。
5. 相同研究版本重复提交必须幂等；输入变化后旧提案不能误应用。
6. 单博主模式来自综合报告中的“重复结构”，不能再把每条帖子的描述长句当成概念身份。
7. 每个博主模式至少有 3 条不同帖子证据，并满足现有深度证据和分层闸门。
8. 前端能看见待审核提案、最终处置、失败闸门、知识定义、排除项和证据回链。
9. 历史数据先 dry-run，再人工审核应用；不允许 fixture 进入生产 Knowledge。

## 不做

- 不为补数量而运行所有 Evaluator。
- 不自动修复 Evaluator 发现的问题。
- 不从点赞相关性推导因果。
- 不把单博主结论直接升级为跨博主规律。
