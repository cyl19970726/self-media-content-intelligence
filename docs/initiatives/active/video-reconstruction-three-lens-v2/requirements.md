# 单帖三镜头 V2 · 需求

关联 Issue：[GitHub #64](https://github.com/cyl19970726/self-media-content-intelligence/issues/64)

## 问题

当前两轮视频重建已经能恢复较完整的内容，但产品链路仍把关键画面留在独立图库，把编导逻辑从 Probe 兼容投影，并让画面与剪辑依赖可选 Evaluator 才可能形成结构。结果是 Builder 明明检查了视频，却无法独立交付完整、可读、可审计的三镜头报告。

## 用户故事

1. 作为研究者，我希望内容还原把关键帧、局部裁切和操作前后状态编入正文，从而无需在文字与图库之间反复跳转。
2. 作为内容创作者，我希望理解视频如何通过钩子、承诺、推进、证明、高潮和收束改变观众认知。
3. 作为剪辑研究者，我希望理解画面、字幕、UI、口播、声音和转场各自承担什么任务，而不是只看到技术抽帧。
4. 作为知识系统维护者，我希望 Builder 即使跳过 Evaluator 也能交付三镜头，且任何缺口不会被旧 `ready` 标签掩盖。

## 功能需求

### R1 · Builder 三镜头

- Builder 必须生产内容还原、编导逻辑、画面与剪辑三个一等结构。
- 三个结构必须共享同一个冻结证据 revision。
- Evaluator 可选，只检查候选，不首次生产三镜头内容。

### R2 · 两轮方法

- 第一轮必须无分类先验地发现认知变化、载体、意义变化、关系、冲突、边界、指代和遗漏风险。
- 第一轮必须分别产生内容、编导、剪辑待验证问题。
- 第二轮必须把三组问题合并、去重后执行定向采集。

### R3 · 多模态内容还原

- 视觉型核心知识必须绑定关键帧或局部裁切。
- 操作型知识必须使用 Before / During / After，或明确标记中间桥接未知。
- 报告支持 `text`、`single_frame`、`annotated_crop`、`before_after`、`operation_sequence`、`frame_strip`、`claim_boundary`、`unknown`。
- 图片必须说明“证明什么、重点看什么、不能证明什么”。

### R4 · 编导逻辑

- 必须包含观看前后、钩子、问题、承诺、推进、证明、高潮、回报与结尾闭合。
- 每个阶段必须有时间范围、观众问题、编导功能、认知变化和证据。
- 不允许用相同文本机械填充多个字段。

### R5 · 画面与剪辑

- 必须包含信息载体分工、意义镜头、UI 状态、结果首次出现、节奏、转场、声音和缺失桥接。
- 技术 scene detection 不得直接被称为真实切镜、场景数或剪辑节奏。
- 运动和转场证据应使用连续帧或有界时间区间，不能只靠一张中点截图。

### R6 · 确定性校验与状态

- 三个镜头分别校验 Schema、引用、时间、媒体指纹和最低语义覆盖。
- 任一必需镜头为空时不得标记 Builder 完整。
- `not_applicable` 必须有证据化理由。
- 跳过 Evaluator 时使用 `BUILT_UNEVALUATED`，不得生成占位评估 Artifact。
- 旧 Artifact 必须准确显示实际覆盖，不得冒充 V2 完整结果。

### R7 · 单帖页面

- 内容还原必须图文混排，关键图片与对应知识相邻。
- 原始图库、完整文字稿和冗长底层报告默认折叠。
- 页面顺序为：基础事实与版本、三镜头状态、内容还原、编导逻辑、画面剪辑、知识关系、原始证据与 Evaluator。

### R8 · 真实回归与可观测性

- 两条开发视频和一条 Holdout 必须在冻结合同后完成 Builder 回归。
- 必须记录 Host、Probe、采集、OCR/音频、三镜头生成、Validator 和总时长。
- 必须记录图片数量、重复采集比例、局部修复次数和各镜头缺口。

## EARS 验收标准

1. 当 V2 Builder 完成时，系统应在不依赖 Evaluator 的情况下返回三个非空、可审计镜头。
2. 当核心知识主要存在于画面或 UI 中时，系统应在正文相邻位置展示可解析视觉证据。
3. 当多个镜头请求相同时间范围时，Host 应只执行一次等价采集并保留多镜头用途。
4. 当任一必需镜头缺少证据、结构或有效边界时，Validator 应拒绝 Builder 完整状态。
5. 当 Evaluator 被跳过时，系统应保留完整 Builder 候选并标记为 `BUILT_UNEVALUATED`。
6. 当打开旧 Artifact 时，页面应明确显示缺失镜头与兼容边界。
7. 当打开单帖内容还原时，用户应先看到图文叙事，而不是默认展开的底层 Markdown 或帧图库。
8. 当三条真实回归完成时，Holdout 应在未读取旧人工报告作为 ground truth 的前提下通过 Builder 三镜头校验。
9. 当回归结束时，系统应输出可用于 session forensics 的阶段耗时和质量记录。
10. 当提交验收时，代码文件不得超过 1000 行，仓库检查、类型检查、测试、Lint 与生产构建应通过。

## 非目标

- 不判断视频为何爆款，不直接生成复刻建议。
- 不外部核验产品、医疗、商业或因果主张。
- 不自动修复 Evaluator findings。
- 不在合同未经三视频验证前批量重跑所有博主。
- 不重写 Git 历史，不迁移或删除用户工作区文件。
