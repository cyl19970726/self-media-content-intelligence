# 单帖读者报告 V2 · 需求

## 问题

当前页面证明了流水线可以运行，却没有把结果组织成读者能快速理解、判断和复用的研究报告。技术状态、审计记录与正文混排，真实原帖信息缺失时仍会显示正式晋级。

## 用户故事

1. 作为内容创作者，我希望首屏知道帖子讲什么、为什么值得研究、哪里有效、哪里不足。
2. 作为研究者，我希望内容、编导、画面剪辑的结论旁边就有对应画面和时间码。
3. 作为审计者，我希望仍能追溯 Builder、Evaluator、Gate、知识单元和逐字稿，但它们不打断默认阅读。

## 验收标准

### R1 · 真实身份

- 当原帖标题、封面、正文或表现数据缺失时，系统应明确标记来源不完整，并不得把“流水线通过”表达成“单帖产品 Gold”。
- 当预览工具已知真实标题、博主主页、发布时间和互动数据时，系统应把这些事实投影到页面，而不是使用视频 ID 占位。

### R2 · 默认读者路径

- 当读者打开单帖页时，系统应先呈现原帖身份、一句话结论、有效之处、不足和可复用结构。
- 默认正文应避免 Builder、Evaluator、Gate ID 和 evidence ref 等内部术语。
- 核心报告之后，系统应以独立折叠区提供研究审计。

### R3 · 三镜头证据

- 当内容还原展示一个关键步骤或状态时，系统应在结论附近显示可读关键帧、时间码和证据边界。
- 当编导阶段包含证据引用时，系统应为阶段选择对应画面，并呈现观众认知变化。
- 当画面剪辑包含语义段、转场、节奏或操作状态时，系统应使用时间轴和前后帧表达，而不是只列文字和技术指标。

### R4 · 状态语义

- 系统应区分流程状态、来源完整度、分析可信度和知识晋级状态。
- 当只有音轨存在但声音语义未知时，系统不得显示“非旁白音频完整”。
- 当 OCR 文件存在但没有有效识别行时，系统不得显示“画面文字完整”。

### R5 · 可读性与可访问性

- 默认核心报告应有章节导航，附录默认折叠，且不显示常驻重复警告侧栏。
- 页面在 320、768、1024 和 1440 宽度下应无横向溢出。
- 所有模式切换应使用可访问按钮状态，页面不得产生新的控制台错误。

## 非目标

- 不修改 Builder 或 Evaluator 生成内容。
- 不伪造缺失的发布正文、封面或外部效果证明。
- 不在本阶段启动单博主或多博主批处理。
