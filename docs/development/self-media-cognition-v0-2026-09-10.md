# 自媒体认知 V0：从理解内容走向创作判断

状态：基于已完成真实使用记录的研究初稿。不是新增产品合同、已晋升规律或功能开发清单；不改写 Builder、原始报告或现有知识裁决。

这里暂将用户所说的“第一技能恢复”理解为现有内容还原技能：完整理解内容表达了什么、展示了什么、如何组织，以及证据与未知。若该词特指另一个技能，需要调整这个范围。

## 1. 我们要建立哪种认知

一份报告的用途至少有两条：学习内容本身，例如 Agent 管理、RAG 组件关系、两遍录制法；学习作者的表达，例如结果差距、受众分流、失败纠正、叙事冲突。应用到自己时，还需要判断与我们的目标、受众、素材、技能和成本是否相容。

因此把问题串成：内容提供什么价值 → 用什么组织、证明和视听表达交付 → 有什么依赖与边界 → 我们准备借用哪一部分 → 实际应用后得到什么反馈。

单点借用不必等待普遍规律成立；它可以是有理由的创作试验。提取规律需要更严格的比较和反例检查。一次试验成功也不能自动晋升为普遍规律。

## 2. 已有案例带来的认知

| 候选认知 | 案例依据 | 当前可用范围与未知 |
| --- | --- | --- |
| 内容价值、传播表现和生产效率需要分别判断 | 张咋啦基本盘“说两遍”提供自由口述→AI清理→提词重录的生产路径；低位木兰有可理解的叙事动机与冲突 | 可把两遍法作为自己的生产实验；未验证作者自述工时，不能因低赞断言无内容价值 |
| 教程的一个研究对象是观众能否建立任务与依赖关系 | Codex从问AI到管理AI；RAG涉及模型、嵌入、向量、工作区及资料处理 | 报告支持复述关系；观众是否真正学会、是否能独立完成仍需使用测试 |
| 失败与纠正可以提供识别方法边界的材料 | Gemini改图出现文字消失、失败后修正；RAG不同资料状态对应不同回答 | 可以借用失败—纠正的证明组织；尚不能声称它独立提高信任、完播或流量 |
| 开头的借用依赖后文可兑现的材料 | Slides先展示审美差距，再介绍模板资产，并按小白/有coding agent分流 | 若我们有可见差异和真实交付物，可实验这种组织；没有对应材料时不能只照搬承诺 |
| 生产流程和成片表达是两个观察对象 | 两遍录制法描述生产流程；其他视频中静态前后画面不保证连续操作 | 能恢复可见状态，不保证恢复拍摄、提示、运行、返工全过程；复现可能需要源外验证 |
| 时长、题材和表现的关系需要按任务与条件研究 | 秋芝40分钟Codex和18分钟DeepSeek处高位；张42分钟低回放之外还有30分钟高位表层样本 | 足以反对“长就差”的笼统判断；尚不足以说明长更好，也未排除时期、账号和分发混杂 |

这些认知的价值在于帮助我们提出更准确的创作问题。它们暂不进入 active 知识，也不作为已证实的传播机制。

## 3. 用创作任务反推信息缺口

| 创作任务 | 决策所需信息 | 当前已有 | 需要补足或实际检验 |
| --- | --- | --- | --- |
| 单点模仿一个开头、证明段或转场 | 借哪段、解决什么问题、依赖哪些素材、前后如何衔接和兑现 | 时间段、原文、画面、部分作用说明 | 为具体创作选择借用范围；映射我们的素材与后文；明确哪些保留、哪些改变及原因 |
| 学习视频教的方法，用于自己的生产 | 操作步骤、输入输出、工具条件、缺失动作和结果判据 | 两遍法、RAG等原文已有部分步骤与边界 | 用自己的材料实际复现；记录不可运行、额外步骤、工时与质量变化，不把还原当复现成功 |
| 提取条件性规律 | 清楚定义的研究问题、同类任务对照、支持与反例、分母和混杂 | 单博主分层、局部综合及原证据 | 现有知识的条件是否可操作；主动寻找反例；形成可被修正的条件假设，而非只收集相似形式 |
| 诊断自己的草稿或成片 | 希望观众知道/感受/做什么、实际哪里卡住、哪些决定可改 | 外部案例和部分表达分析 | 自有草稿、目标观众任务、独立阅读/观看反馈；将反馈对应到具体片段 |
| 选择适合自己的方向与表达 | 我们的经验、信任来源、可展示成果、制作资源和持续性 | 现有内容包已有目标、平台、假设与知识绑定 | 检查这些信息能否参与参考选择；补齐尚未明确的自身约束，避免另建一套创作系统 |

上述“缺口”首先指完成决策时信息不充分或不可达，不能直接解释为后端没有字段。应逐项区分：已保存但展示不到、原分析没有回答、需要新采集/实测、需要创作者本人提供。

## 4. 工作台的分工

- 内容还原提供忠实的内容、表达和证据。检查当前技能能否支撑具体问题，缺失处如实标未知。
- 下游研究围绕问题维护支持、反例、适用条件和候选解释；不混入 Builder 正文。
- 具体创作记录我们的目标、参考、取舍、素材缺口和待检验假设。沿用已有内容包及版本绑定。
- 实际反馈记录理解/情绪/操作目标、制作成本、公开传播或商业结果等不同维度；只能判断实际取得的数据。

既有系统已经有 Knowledge 和内容包，不能把下一步理解成从零做知识库或创作区。重点是用一个真实任务检查它们是否能传递足够的信息，且版本、引用与对象状态正确。

## 5. 下一轮最小闭环

先选择一次真实创作，写清受众、希望产生的变化、可用素材与成本约束。选一个主要借用点，只围绕它补证据和形成一份可执行的草稿或分镜。单点可选“失败—纠正—边界”的证明段，或有真实结果可展示时借用Slides的结果差距开头；具体选择取决于我们的创作题目。

让独立 Agent 只使用工作台完成这个任务，逐步记录在哪一条信息上被阻断。另一位读者只看草稿/成片，检验能否理解目标内容与边界。随后修复最高优先的信息断点，再复验。

验收要求：能说清想达成什么、具体借用了什么、为何适合、哪些材料尚缺、如何验证；不要求一轮建立通用规律或证明传播效果。规律研究另取其中一个问题，用同博主对照和反例继续推进；跨博主扩展由问题需要驱动。
