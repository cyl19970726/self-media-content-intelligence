## 修订与旧版兼容

API 只选择显式保存的完整源文件，不即时改写 Builder。每个修订以原文件 SHA-256 定位，保存原文、修订文、双方摘要及修订原因。原文件变化后旧修订自动不适用；修订校验失败明确报错。原始证据库内容地址文件未改动。

- 读取实现：`src/server/report-source-revision.ts`。
- 可复现脚本：`scripts/repair-report-sources-20260911.py`。从项目根目录运行，显式设置 `SIGNAL_ROOM_EVIDENCE_ROOT`；需要本机现存两份旧证据和908运行源文件。
- 默认保存到 `.runtime/report-revisions/<originalSha256>/`，共8份文件。部署或迁移时需要一并迁移该目录，或设置 `SELF_MEDIA_REPORT_REVISIONS_DIR` 指向保存位置。Git包含脚本和读取逻辑，不包含本地媒体或完整报告副本。
- 本轮清单：`.runtime/source-repair-20260911/revision-ledger.json`。
- 页面显示修订原因与旧评估边界；新报告的旧总览标过期，旧评估不赋予当前版本晋升资格。旧评估与原报告保留为历史材料。
- 项目技能补充了转写完整性、阶段证据支持、首次时刻和修订后评估失效的规则。语义支持仍需复核，不能单凭 ID 存在或时间范围自动判定。
