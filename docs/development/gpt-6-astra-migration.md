# GPT-6 Astra migration

Active Codex defaults for video Builder, video Evaluator/repair, image-post reconstruction, creator synthesis and its evaluator are now `gpt-6-astra` with existing `medium` reasoning. Evaluator receipts record the same default. Per-role environment overrides remain supported; `.env.example` lists all five model settings. Existing deployments with explicit model overrides must update those values and restart workers to adopt Astra. This supersedes Terra defaults described in older initiative records; historical reports and acceptance records remain unchanged.

The project uses Codex CLI rather than direct OpenAI SDK requests. No API endpoint, authentication, prompt, report schema, or media/transcription model change is needed. Existing report artifacts are not regenerated by this migration.

Official migration guidance: https://developers.openai.com/api/docs/guides/latest-model

Astra does not accept `none` or `minimal` reasoning; use `low` if those values were configured externally. The built-in `medium` remains supported. Direct API integrations added in future must use Responses for tool calling and omit unsupported sampling parameters, per the official guide.

Validation covers TypeScript and executor argument/override regressions. A small CLI smoke request checks local access separately; it does not establish full video-analysis quality equivalence.
