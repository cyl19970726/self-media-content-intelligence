# 认知完整性与阅读顺序：一轮小闭环

目标：核清当前 12 篇单帖中“讲过什么”与“实际还原了什么”的差距，修订六篇已有明确来源的遗漏，并改善综合页结论与依据的阅读层次。

原则：

- 区分来源已提供但报告遗漏、已有信息难找、来源无法回答三类问题。
- Builder 修订来自冻结字幕和原帧，保留原始产物与修订指纹；API/前端不补写知识。
- 不将局部修订宣称为全片独立验证；旧评估与派生总览不沿用。
- 保留完整三个 Lens 和连续内容还原；综合结论不因页面调整而被改写。
- 本轮不扩展发布流、不重做整个工作台、不启动新一轮采集。

交付与验收：

1. 全部 12 篇文字与证据差距审计：记录具体遗漏及可定位来源，不能仅按篇幅判断质量。
2. 六篇 Builder 修订：读者能够实际读到五项能力、配置限制、需求条目、提示词约束和操作条件；Schema/引用检查通过，原文件保留。完整审计见 [知识还原审计](creator-knowledge-audit-2026-09-14.md)。
3. 阅读调整：空总览不占首屏；综合结论优先、依据可展开、表现附近有样本口径。
4. 实际打开修订单帖与综合页，检查知识可读、证据入口和无横向溢出。

状态：已交付这一轮六篇源修订与阅读调整。Sol 对照全部 12 篇后，与 Terra 分工修订六篇；Luna medium 对固定候选独立复核。两处语义复核发现（主板说明时间范围、未经确认的技术缩写规范化）修正后，六份候选均通过局部复核。不是完整 Evaluator 晋升。

产物：运行时 `knowledge-repair-20260914/published-revisions.json` 记录六篇修订指纹，`review.json` 绑定独立复核结果，`validation-results.json` 记录 Schema、媒体与引用检查。修订由既有 `report-source-revision@1` 哈希绑定机制读取；12 份原始 reconstruction 文件全部保留不变。博主综合仍引用原始版本，页面明确提示尚未重新归纳。

阅读调整：缺失总览不占首屏，失效总览仅显示简短说明；综合结论与可展开依据分层，表现部分展示作品/指标/样本口径。正文保留段落换行。实际阅读还定位了投影层将整段正文复制成每张图的证明说明的问题，现已去掉自动补写，未产出逐帧说明时如实显示缺失。

## 已确认的工作方式与下一轮使用问题

用户确认由主 Agent 作为实际使用者形成认识、与用户讨论并指导下一步；单帖与综合 Builder 交给代码组织的 `codex exec` 服务或临时 subagent。该约定已沉淀为项目内 [reader-led-workflow](../../.agents/skills/reader-led-workflow/SKILL.md)。

主 Agent 当前判断：读者已经能在修订单帖中获得更具体的知识，但综合仍不能充分回答“先读哪篇、这些知识如何关联、该博主的表达适用于什么问题”。下一轮应先确认修订来源能被综合输入实际绑定，并补读关键显卡表；再组织综合 Builder，最后实际阅读用户页面验证这三个问题。不能仅修改展示或调用旧输入的服务就算完成。本段是下一轮方向记录，未宣称新综合任务已经启动。
