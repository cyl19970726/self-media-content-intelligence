# 博主分析批量前验收 · 2026-09-14

## 验收范围与结论

本轮检查单博主分析与多个独立博主任务的批次入口，没有扩展跨博主比较、创作或发布。独立读者实际使用秋芝2046、张咋啦的历史及版本化报告，并检查阿柚失败任务、提交预检和恢复入口；代码审查覆盖队列、提交幂等、采集完整性和综合证据验证。没有启动真实新博主采集或付费 Builder/Evaluator，因此不宣称新批次已端到端完成。

阅读主链可用：秋芝70条可见作品、21条选择集、12条深读的分母能够区分，综合引用进入单帖后可以返回同一批次。发现的问题已作以下有界修复。

## 根因与处理

| 问题 | 根因 | 修复 |
| --- | --- | --- |
| 同博主两个“唯一研究页” | 静态slug和平台creator ID按不同id拼接，卡片忽略服务端entries | 按主页身份合并主卡，当前入口固定run，历史样本保留为单独折叠链接，不混合分母或覆盖旧分析 |
| 失败页只有说明，没有恢复动作 | 仅needs_user显示继续按钮 | 复用服务端operation选择恢复/重试；外部服务等待不自动重试，提供用户确认已恢复后的继续操作 |
| “深度”及提交措辞不清 | 冻结样本、Builder资产和评估状态混称；全复用仍写开始分析 | 明确Builder已构建、独立评估另计；新建/复用/混合分别命名；列出具体未完成上游阶段 |
| 批次可能产生隐藏重复run | operation检查和batch持久化之间先执行run intake，跨连接竞争或中断没有共同事务 | 同一SQLite连接内BEGIN IMMEDIATE，先查operation，再惰性执行intake和batch写入；整体回滚，重试返回原批次 |
| 失联任务无限自动重领 | lease到期不检查maxAttempts | 到上限停止自动恢复，保留failed、原因、事件及显式resume；其他博主可继续领取任务 |
| 部分采集被显示成full | 只检查点赞覆盖率，采集停止原因未进入analysis合同 | 从corpus.denominator传播stopReason/corpusCompleteness；预算停止、静默或旧版缺失元数据均partial；仅明确结束、观察收敛且指标覆盖达标才full |
| 综合错误绑定别帖/别批次 | 只检查引用字符串包含重建目录 | 按当前batch中每个帖子的reconstructionArtifactRef核对引用；缺失原产物、错帖和错批次不能通过 |
| 少量媒体缺失时新状态误拦截 | bounded分支只识别旧ready，不识别verified | 统一两种已验证状态，保留四组选样覆盖要求和媒体未知边界 |
| 表层标签引用了错误字段 | 文字分类结果引用mediaType；无标题时没有使用已声明的visibleText | 标签绑定实际文字来源，媒体兜底仍引用mediaType；表层线索不替代正文分析 |

“正式ready”继续表示原研究合同下的验证资格，不新增“已读完所有历史视频”的含义；清单有边界时只能解释已观察范围。旧产物没有完整性元数据时保持未知，不猜测其采集是否到达终点。

## 验证证据

- 原因与初始页面复现：`.runtime/creator-readiness-20260914/user-audit.md`、`pipeline-audit.md`。
- 独立浏览器使用唯一TaskSpace34，核对当前/历史入口、全复用CTA、构建计数、引用往返及恢复状态；没有点击真实采集/重试按钮；最终看到条件恢复按钮后，TaskSpace34已成功关闭。
- 原子提交回归使用共享SQLite连接与真实CreatorResearchService：第二位intake失败后，run、queue、event、batch写入都回滚；同operation随后可以重试；另一连接已获胜时不会再次调用intake。
- 租约回归覆盖耗尽上限、其他博主继续执行、明确人工resume和外部数据库连接生命周期。
- 综合回归先复现错帖/错批次/无源报告引用被误通过，以及verified媒体边界误拒绝，再修复。
- 全仓81个测试文件：425通过、1条件跳过；构建、全仓lint、类型、repo与docs检查通过。随后局部UI恢复修订与入口回归9通过、2项因该次未加载外部证据而跳过；最终构建及全仓lint再次通过，Web/API/Worker/CLI入口冒烟通过。

## 当前运行条件与下一批执行原则

检查预览使用主库隔离快照，API4320关闭内嵌Worker，当前未发现独立Worker；新任务即使入库也不会自动执行。默认RedFox主站网络可达，但当前配置缺少REDFOX_API_KEY。此为当前配置缺失，不据旧阿柚超时记录推断服务仍离线。

Builder CLI及登录、本地媒体工具可用；本轮没有实际调用付费模型验证分析结果。启动新批次前，应确认正式运行库、采集通道和登录/凭据，以及Worker已就绪。可使用项目现有的可用采集通道，不为通过预检临时更改模型强度或增加并发。

收到多个博主后，以每位独立的“可见清单与范围→高中低选择集→高/中位附近/均值附近/低四组深读→三Lens原报告→有证据的博主综合→实际阅读验收”为闭环。优先完成第一位，确认真实采集与生成链路后再放开其余队列。采不到、未深读、未独立评估的部分明确记录，不把页面可读或任务ready解释为全历史视频均已验证。
