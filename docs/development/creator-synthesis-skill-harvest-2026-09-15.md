1. **五部分不是凭空设计的栏目，而是一次真实综合的交付合同。** 用户先否定直接套用 `analyze-creator-videos`，要求按讨论结果分析，并允许给独立执行者明确任务（会话 L8201、L8203、L8214）。随后产物固定为 `value / knowledge / patterns / performance / next_questions`，12 条深度样本和 21 条比较样本参与，10 条 finding、69 个引用被解析；代码提交 `c857133e` 同时增加 Schema、校验、页面和执行器。对应项目记录是 `docs/development/creator-cross-post-research.md`。这证明五部分曾经完整跑通，不证明它是所有创作者的唯一分类法。

2. **实际阅读改变了验收标准。** 第一版综合完成后，用户要求 Host 作为读者回答“获得哪些认知、还有哪些疑问、认知摆放是否合理”（L8871；L9741 再次强调并要求回查触发机制）。物证显示 Host 随后打开综合页、读取正文、进入具体单帖（L8874–L8895），并在 L8900 明确发现：报告擅长讲验证边界，但具体可学知识被抽象成方法和边界。后来产物没有只改文案，而是审计 12 篇、修订 6 篇具体知识，再重新综合；用户在 L8945 授权下一轮。由此得到的生成规则是：综合前必须能逐帖复述具体知识；若源报告只写“列出五项”，回交单帖 Builder，综合层不得暗补。

3. **新版综合把“知识关系”推进为可使用的学习路径。** `.runtime/reader-next-20260914/synthesis-notes.md` 逐帖比较了“能跑/长期可用”、Mac 立场更新、在线/本地责任条件和“判据→案例”的讲解方式；候选五部分把这些关系写进 finding，并新增阅读顺序和学习型问题。Host 阅读候选后发现具体条件藏在折叠证据、阅读顺序缺失，退回 Builder；页面复验又发现导航把“权限”错误归到另一篇律所帖，再次退回，最终改成该帖实际支持的“律所共用、人工复核与溯源”。这条错误链记录在 `docs/development/creator-reader-next-2026-09-14.md`。它验证了：引用可解析仍不够，每条综合结论和导航必须由对应帖子自身支持，且 Host 要在用户实际页面重读。

4. **表现与学习价值必须分开。** 最终候选把高互动和 0 赞样本并置，只作描述性比较；0 赞的电商、律所和后期服务器仍提供产量、组织责任和双机分工知识。公开点赞没有被用来推导曝光、完播或因果模板。这个边界同时存在于实际候选、Schema 的 `boundary/openQuestions` 和项目记录，因而属于已实践的方法。

5. **自适配、多标签分类来自明确用户纠正，但不属于首轮五部分运行的验证结果。** 用户要求“现有分类无法覆盖时可以增加”（L11364）、“可以属于多个分类”（L11366），并要求由 Builder 执行时自行适配（L11386）。因此新 skill 应要求从冻结作品证据生成开放标签表，允许一帖多归属和诚实未知。当前工作区已有 `topic / format / commercial_signal` 三轴 Schema 与校验，但这些改动尚未提交，历史候选也没有 `portfolioClassification`；所以可以把它写成用户确认的生成合同，不能声称已在上述单车酒吧综合中跑通。

## 可直接写入 skill 的方法

- 冻结输入并通读每篇已构建样本的三个 Builder Lens 与评估边界；作品清单和表现分层只提供分布背景。来源修订后，旧综合与旧评估失效，需固定新版本再生成和复核。
- 先形成逐帖可复述理解，再按实际问题连接帖子：共同条件、互补机制、适用场景差异、时间变化、明确冲突、尚未比较。不要用表达套路代替知识，也不要把所有差异抹平成一致。
- 五部分各自回答不同问题：`value` 是持续解决什么；`knowledge` 是具体知识、条件和关系；`patterns` 是内容、编导、画面与剪辑的重复做法及例外；`performance` 是带口径和混杂因素的描述性差异；`next_questions` 是由已读认知产生、可继续研究的问题。每条 finding 自带事实类别、置信度、逐帖支持、反例、边界与开放问题。
- 自适配分类与五部分并行：先从当前冻结材料建立紧凑标签表，再逐帖多标签标注；标题证据与深度 Builder 证据分层，证据不足可以不分类并说明未知。同义标签膨胀、跨帖借证和强于可见文案的商业判断应拒绝。
- Builder 生产候选，Reviewer 绑定确切候选和输入版本独立检查，Host 在实际工作台阅读并追入单帖。Schema 通过、执行成功或 Reviewer 通知都不能代替最后这一步。

### 一个具体例子

“32B 多卡方案”和“文生视频单卡 24GB 门槛”表面矛盾。逐帖阅读后，综合发现前者讨论 32B FP16 的低价凑显存方案，还受亮机卡占槽、被动散热和维护限制；后者讨论本地文生视频的软件路径，强调单张执行卡和 ComfyUI 学习成本。正确 finding 归入 `knowledge`，statement 写“多卡能否用取决于任务和软件路径”，两帖分别作 support，边界注明技术数字仍是作者主张；若研究“作者如何让读者理解”，同一材料还可支持 `patterns` 中“先交代决策条件再给型号”。这种多归属发生在不同分析轴，不应复制一句结论到多个栏目。
