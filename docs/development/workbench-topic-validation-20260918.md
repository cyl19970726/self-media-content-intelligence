## 实际发现并处理

1. **深链接无法打开。** 根页面可打开，直接访问 `/creators/...` 返回 500。隐藏目录 `.codex/worktrees` 被 Express 绝对 `sendFile` 的 dotfile 校验误伤。改为固定 `index.html` + 明确静态目录 root；回归检查深链接、API、缓存头和隐藏文件不泄露。
2. **报告与执行入口断开。** 单帖页面只有阅读入口；启动接口存在但无按钮。补充“用当前方法重新研究”，显示提交中/错误并跳转本次执行。仅启动此帖。
3. **执行页身份不清楚。** 主标题是内部 workflow 名称。补充中文流程名称、原帖标题与绑定原研究的返回链接，技术 ID 保留在次要审计位置。
4. **原帖封面未进入证据清单。** 首次真实调用返回 `consistent`，引用 `post-cover.webp` 后被 Host 以 `SOURCE_CONSISTENCY_EVIDENCE_REF_INVALID` 拒绝。封面确实被准备在 cwd，却未登记到白名单/输入摘要。修复为两轮均冻结并提交封面，校验其摘要与引用，同时继续要求视频帧证据；只有封面时不得发起来源判断。
5. **失败原因没有可操作解释。** 原先只给诊断编号。为已知证据引用、证据变化、模型超时添加固定安全文案；未知错误仍不暴露原始私有诊断。

6. **复用候选被误读成模型生成。** 真实 build 阶段复制已有报告，没有调用 Builder。入口文案明确可能复用；阶段展示根据复制事件与模型调用记录区分，父阶段需要读取关联子运行事实，不能凭零耗时猜测。
7. **阅读资产会丢失研究范围。** 新运行、父子运行与资产锚点导航保留 `creatorRunId`，避免回到全库数百条记录。
8. **复制旧候选会携带旧 skill 包。** 排除候选根目录 `.agents`，让本次冻结方法重新 stage；其他证据与隐藏文件保留，旧候选不修改。

## 阅读体验与质量边界

已有报告能连续阅读内容还原，目录只定位；编导结构与画面剪辑可切换，画面在结论旁展示，原帖来源和研究解释分开。阅读者能够复述“普通连接→软硬两态→三构件互锁→应用设想”的链条，也能识别承重、历史来源、帐篷用途没有被同等验证。

旧报告仍有明显内容局限：产品正式名保留未知，ASR 有错误专名，参数/耐久段称 OCR 失败；这属于 Builder 证据与结论的质量，不能由 UI 偷改。首轮来源检查已经提到 Y-zipper，但该失败结果不能直接替换 Builder 正文。

工作台仍不是任意选题的通用研究编辑器：本次题目落在已有视频素材上。执行状态不等于研究验收，修订完成不等于再次独立复核；需要结合实际产物与原始证据判断有效性。
