# 《它不是没干活，它是在认真空转》编导执行方案 V2

## 1. 成片结论

做一条 58–62 秒的小红书竖屏视频，采用“上方证据、下方人物”的动态双层结构。借用 AI 红发魔女高表现内容的功能机制：零铺垫冲突、结果先行、一句一证据、人物负责关系和情绪；不复制其人物身份、红发、配色、字幕模板或公开视频素材。

本条不是宣传一个万能 Skill，而是交付一个可立刻执行的止损问题：

> 过去十分钟，哪个目标产物真的发生了可验证变化？

若暂时答不出，先暂停新增工作，审计后再决定继续、分拆或停止。等待构建、人工授权、外部服务等合法等待不应被误判为空转。

## 2. 事实口径

### 自有会话

会话 `019ff003-c337-76e2-888e-81bbd6584076` 有 11,396 行、1,430 次 exec、336 次 wait、16 次 compaction、102 次 patch，涉及 39 个文件。重复诉求簇共有 8 个成员；7 组相邻表达被判定为 restated。

正确结论：大量活动和文件修改真实存在，但“移动端内容可读”这个目标后来仍被用户指出没有解决。不能说成“Agent 什么都没做”或“用户额外重复了八遍”。

### 外部来源

- OpenAI Codex #27588：报告者称任务运行 2–4+ 小时仍未进入文件编辑，并在压缩后重复读取规则。
- OpenAI Codex #31351：报告者称约 3 小时反复自动压缩、没有实际进展；不能据此声称零文件改动。
- Claude Code 官方 troubleshooting：`Autocompact is thrashing` 是 Claude Code 的一个不同故障状态；官方说明反复填满上下文会触发停止重试，避免无进展循环。它不是对 Codex 个案根因的共同确认。

其他 issue #37600、#14120、#5957 只放在说明区或评论补充，不在 60 秒主片堆叠。

## 3. 60 秒定稿口播

共 214 个汉字；英文产品词与数字按正常节奏读。目标实录 56–60 秒，允许 2–4 秒无口播阅读空间，总时长 58–62 秒。不得以 1.2 倍速或逐短句碎切强塞。

> AI 最可怕的不是罢工，是认真工作两小时，一个文件都没改。
>
> 这不是段子。Codex 公开 issue 里，有人跑了两到四小时，反复读规则、压缩，仍没进入文件编辑。
>
> 我的剪辑任务也有 1430 次执行、336 次等待、16 次压缩；同类画面要求共有 8 次表达，7 次相邻表达被判为重述。
>
> 但它也改过 39 个文件。所以问题不是“没干活”，而是活动量不等于目标闭合。
>
> 我后来新开一个 Session，用 Session Forensics 对照目标、工具、文件和用户纠正。
>
> 这次目标是“手机上内容可读”，但后来用户仍说录屏不可读。此时先暂停新增工作，再决定继续、分拆还是停止。
>
> 长任务别只问“还在跑吗？”问它：过去十分钟，哪个目标产物真的变了？

首句中的“两小时、一个文件都没改”只对应 #27588；卡片必须同屏标 `用户报告 · Codex #27588`，不能与 #31351 混拼。

## 4. 最小价值闭环

本条必须在 35–50 秒完整展示同一个病例，不把价值推迟到下一集：

| 层 | 卡片内容 | 证据边界 |
|---|---|---|
| 目标 | 手机竖屏里，上方内容裸眼可读 | 来自用户明确要求 |
| 物证 | 后续用户仍指出“录屏被压窄后不可读” | 最小必要转录；不展示会话全页 |
| 活动 | 1,430 exec / 39 files | 只证明活动，不证明有效进展 |
| 判断 | 活动量 ≠ 该目标已闭合 | 对上述观察的系统推断 |
| 动作 | 暂停新增工作 → 核对目标产物 → 继续 / 分拆 / 停止 | 决策启发式，不是普适强制规则 |

### 声画接口规则

- 人物使用原视频带背景的圆角矩形，不抠像，避免头发/下巴硬边。
- 若原口播不是一条连续实录，优先重录这一版；其次用 F 全屏证据遮盖句间接口，不用高频 jump cut。
- 上区横屏屏录仅允许 0.5–0.8 秒交代环境，随后切语义 ROI。完整桌面缩进竖屏属于不合格。
- 字幕在上下区边界，54–60px，单行 10–16 汉字，最多 18；关键证据卡不重复字幕全文。
- 一句只有一个主运动。人物缩放、内容切换、字幕强调不得同时争抢。

## 9. 隐私、引用与权利 Gate

发布前由内容负责人逐项签字：

- [ ] 出镜者同意视频、声音和肖像公开发布。
- [ ] 会话素材仅保留支持主张的最小句子；删除 session ID、绝对路径、用户名、邮箱、密钥、未发布项目名和截图元数据。
- [ ] 情绪化原话若非论证必要则不公开；必要时改为不带身份的概括。
- [ ] GitHub 与官方文档只做最少摘录，显示来源和链接/编号；不复制整页，不暗示厂商共同确认同一根因。
- [ ] BGM、音效、字体、屏录、人物原片均有明确来源和发布权；许可记录跟随项目保存。
- [ ] 第二位复核人只看“准备发布的导出版本”，确认遮挡在编码后仍有效。
- [ ] 未通过时删除外发包，保留本地工作文件；不得先发后补授权。

## 10. 发布实验

唯一变量只改 0–3.5 秒第一镜：

- A：`2–4+ 小时 / 仍未进入文件编辑 / #27588`
- B：`1,430 次执行 / 目标仍未闭合 / 本地会话个案`

锁定项：同一标题、封面副标题、正文、总时长 ±1 秒、后续 3.5–61 秒画面、CTA、声轨、发布时间在同一星期与同一 ±30 分钟窗口；任何偏离写入实验日志。小红书分帖非随机，结论只能写“该批次相关”，不能写因果证明。

- 主指标：后台 3 秒留存；分母为该帖后台显示的有效播放。
- 护栏：完播率、收藏/有效播放、主页访问/有效播放，以及“夸大、不真实、混淆厂商”的负评占有效评论比例。
- 评论编码：一条评论可多标签；由两人独立标记，分歧复核。
- 最小观察量：每版有效播放 ≥3,000；不足则只记录方向，不宣布胜出。
- 成功线：A/B 相对 3 秒留存提升 ≥10%，完播下降不超过 8%，负评率不增加超过 1 个百分点；至少两个可比批次方向一致。
- 停止规则：触发隐私投诉、事实错误或厂商归因误导时立即下架/更正；样本不足或发布条件明显不同则保持未知。

## 11. 发布后复盘

按顺序判断，不用一个互动率概括全部：

1. 入口：3 秒留存是否识别了“认真空转”痛点？
2. 早理解：评论是否能复述“活动量不等于目标闭合”？
3. 价值：是否有人保存或引用最后的止损问题？
4. 信任：是否出现“拼接数字、跨厂商混淆、夸大普遍性”？
5. 执行：成片是否真的遵守上内容、下人物和 360×640 可读标准？
6. 下一轮：只修最差的一层；入口差才换钩子，理解差才改中段，信任差先修证据而非继续加情绪。
