# 《它不是没干活，它是在认真空转》编导方案 V1

## 这条内容要做出的决定

把 `Session Forensics` 从一个抽象的“会话审计 Skill”，讲成重度 Coding Agent 用户能够立刻识别、验证并止损的工作方法。

- 主任务：获客。让正在用 Codex / Claude Code 做长任务的人在前三秒认出自己的痛点。
- 护栏任务：信任。不能把个案包装成“所有 Agent 必然失败”，也不能把工具活动量误说成实际进展。
- 目标观众：已经用 Agent 做过 30 分钟以上复杂任务，遇到过忘目标、反复规划、上下文压缩、验证循环或“界面一直动但产物不变”的创作者和开发者。
- 观众当前认知：Agent 还在运行，就等于任务还在推进；出现问题时，继续提醒主 Agent 即可。
- 要完成的认知变化：工具活动 ≠ 目标进展；执行者很难看见自己的漂移，需要外部会话根据物证审计。

## 痛点是否真实

结论：真实，但必须限定为“长任务中的已报告失败模式”，不能说成每次必然发生。

### 我们自己的病例

会话 `019ff003-c337-76e2-888e-81bbd6584076` 的物证测量：

- 11,396 行记录；
- 1,430 次执行；
- 336 次等待；
- 16 次上下文压缩；
- 102 次 patch，涉及 39 个文件；
- 用户的同类不满形成 1 个重复诉求簇，共重新陈述 8 次。

关键裂缝不是“Agent 什么都没做”，而是“活动很多，但用户反复指出的核心问题没有稳定闭合”：

- 用户明确要求“人物缩小、内容放大，最终服务于内容”；
- 后续仍指出“录屏被压窄后不可读”；
- 再次反馈“这个问题没有解决”；
- 后期又指出口播被切得太碎，任务不得不升层回到四段主轨基础装配。

这能证明该次求解过程发生了目标漂移与局部修补循环；不能证明所有模型、所有长任务都会如此。

### 外部硬证据

1. OpenAI Codex issue #27588：有人报告任务运行超过 2 小时仍没有文件编辑，压缩后重复读取同一批项目规则。
2. OpenAI Codex issue #31351：有人报告约 3 小时反复自动压缩，没有实际进展，消耗约 30% 使用额度。
3. OpenAI Codex issue #37600：长时间扩张计划、治理、证据与审计脚手架，生产实现进展不成比例。
4. OpenAI Codex issue #14120：约 2 小时、连续多次压缩，仍未 patch 文件，并担心理解在“传话游戏”中退化。
5. OpenAI Codex issue #5957：报告称压缩后忘记已编辑的 23 个文件并“lose the plot”。
6. Claude Code 官方故障排除文档明确使用 `Autocompact is thrashing`，并说明会停止重试，以免在没有进展的循环中浪费 API 调用。

反证与边界：官方建议分块读取、带焦点压缩、使用独立子上下文或 `/clear`；也有用户报告长会话多次压缩后仍能继续。因此，问题可缓解，不是必然结局。

## 三个内容方案

### A. 传播型：AI 在认真空转

- 钩子：AI 最可怕的不是罢工，是认真工作三小时，一行代码都没改。
- 情绪：荒诞、角色反转、黑色幽默。
- 证明：外部 issue 的“3 小时 / 0 产出”与自己的执行数据。
- 优势：最接近 AI 红发魔女 Bad Claude 的传播引擎。
- 风险：只讲笑话会让 Session Forensics 沦为概念，收藏价值不足。

### B. 解法型：长任务跑偏，别再追问主 Agent

- 钩子：Agent 长任务跑偏后，最没用的动作就是继续问它“你还记得目标吗？”
- 承诺：用另一个 Session 在一分钟内判断它是真推进还是空转。
- 证明：展示定位、量化、下钻、对质、纠偏五步。
- 优势：搜索和收藏价值强，最接近“具体痛点解法”引擎。
- 风险：开头偏工具教学，陌生观众进入成本较高。

### C. 反转型：防漂移系统自己变成漂移

- 钩子：我给 Agent 加了更多计划、Gate 和 Reviewer，结果它更不交付了。
- 承诺：解释为什么“更多验证”不等于“更可靠”。
- 证明：会话里的流程膨胀、外部 issue #37600 和审计方法。
- 优势：观点更深，能建立方法论人设。
- 风险：抽象、需要观众已经理解 Agent 工作流。

## 推荐方案

选择 **A 的钩子 + B 的交付 + C 的机制解释**，而不是做三条内容的拼盘。

核心命题：

> 它不是没干活，它是在用非常努力的方式偏离目标。

这句话负责传播；真实会话数据负责可信度；外部审计五步负责收藏价值。

## 60 秒口播稿

### 0–4 秒｜冲突钩子

AI 最可怕的不是罢工。

是它认真工作三小时，最后一行代码都没改。

### 4–11 秒｜证明不是段子

这不是段子。Codex 的公开 issue 里，真的有人跑了两到四个小时，Agent 一直读规则、自动压缩、再读规则，就是进不了写文件阶段。

Claude Code 官方甚至给这种状态起了名字：`Autocompact is thrashing`。

### 11–22 秒｜我们的真实病例

我自己的一个长任务更夸张：一万多行会话记录，1430 次执行，336 次等待，16 次上下文压缩。

看起来忙疯了。

但我反复指出“内容要放大、录屏根本看不清”，同类问题还是被我重新说了八次。

### 22–34 秒｜解释机制

因为一旦 Agent 接到目标，它就进入执行者视角。

上下文压缩会丢细节，失败尝试会污染后面的判断；为了证明自己没错，它又会加更多计划、Gate 和 Reviewer。

最后，局部修补替代了真正的目标。

### 34–51 秒｜给出方法

所以我后来不再继续追问主 Agent。

我会新开一个 Session，用 Session Forensics 去看它留下的物证：它调用了什么工具、改了哪些文件、等了多久、用户重复纠正了什么。

再把“它说自己在推进什么”，和“产物到底改变了什么”放在一起对质。

### 51–60 秒｜止损动作与下一集

长任务里，别只问一句“它还在跑吗？”

你应该问：过去十分钟，哪个目标产物真的发生了变化？

答不出来，就该停。下一条，我把这套外部审计五步完整演示一遍。

## 画面方案：不再缩放完整横屏录屏

视觉原则：一句一证据；手机首屏同一时刻只承担一个知识焦点。人物不是固定占位，而是随认知任务动态让位。

### 从 AI 红发魔女真实画面学什么

高表现 Bad Claude 视频不是把人物和桌面各缩成一个小窗口。它的基本画幅更接近：上方约 58% 是被重新裁过的唯一证据，下方约 42% 是人物；字幕压在两区交界。终端、短句数组、路线图和表情包会逐句替换，上方从不要求观众同时读完整桌面。人物保留连续情绪反应，但不承担知识文本。

我们只复制这个职责分配，不复制她的红发、青绿/棕橙配色、圆形头像和具体字幕样式。

### 四种画面状态

以 1080×1920 为母版：

1. **P｜人物主导**：上方 38%，下方人物 62%。只用于开场后的关系建立和结尾判断。人物头肩宽约画布 52%，眼睛落在 y=1280–1370。
2. **S｜标准讲解**：上方内容 64%，下方人物 36%。默认状态。人物使用带真实背景的圆角矩形，不做抠像，避免下巴或头发出现蒙版硬线。
3. **E｜证据主导**：上方内容 76%，下方人物 24%。用于 issue 卡、数字和操作证据；人物只保留表情反应，不放手势密集动作。
4. **F｜全屏证据**：内容 100%，人物暂时消失。用于 0–4 秒钩子、三张用户纠正卡和五步审计总图。

字幕不是第三个大区域。单行字幕跨在内容与人物的边界上，字号 54–60 px，推荐 10–16 个汉字，最多 18 个；不得遮住人物眼睛、嘴和关键证据。

### 横屏录屏的裁法

完整横屏只允许出现 0.5–0.8 秒，用来交代“这是什么界面”。随后必须切到语义 ROI：

- 讲 Session ID，只留 ID 所在行与复制动作；
- 讲调用 Skill，只留指令输入区和返回状态；
- 讲 1430 次执行，只做独立数字卡，不让观众在原始 Dashboard 里找数字；
- 讲用户纠正，只重排成一行一张的消息卡；
- 讲五步法，重做为五个大节点，不从复杂信息图里再扣一块小图。

任何录屏片段在最终 360×640 等比预览下都要裸眼可读。中文正文高度低于约 16 px（对应 1080 宽母版约 48 px）、代码小写高度低于约 12 px时，不得通过验收；应继续放大或重做信息卡。

### 平滑切换规则

- 同一个页面内从概览进入局部：350–500ms `ease-out` 放大，锚点落在将被讲到的文字中心；不做匀速长推。
- 两个不同证据对象之间：120–180ms 方向一致的遮罩切换或直接切，不用假装是同一空间。
- S → E：内容区向下扩张 420ms，人物框同步缩小并下移；两个动画共享同一缓动和终点。
- E → P：先让证据停留 200ms完成阅读，再让人物在 450ms 内放大；不能在关键字还没读完时抢回人物。
- 一次语义句只允许一个主运动；字幕、人物和证据不能同时各自动画。

### 人物主轨规则

- 四段原始口播按完整语义段拼接，只清理接口冗余、明确口误和长停顿；不把每个短停顿都切掉。
- 音频连续性优先于视觉切换。切换上方内容时，下方人物不能同步发生跳帧；必要时用上方全屏证据遮住人物接口。
- 人物框使用原视频真实矩形背景与 36–48 px 圆角；不抠像、不加贴脸描边，避免过去出现的下巴硬线。
- 标准讲解时保留头顶 8–12% 安全空间；下巴到框底至少 10%，不能靠裁切把脸“卡”在边界上。
- 重点证据出现时人物缩小，不是降低透明度。结尾人物放大时，内容卡必须真的退场，不能仍在上方堆字。

| 时间 | 画面 | 认知任务 | 人物比例 | 证据责任 |
|---|---|---|---|---|
| 0–4s | 全屏“运行 03:00:00 / FILES CHANGED 0”动效，终端字符高速滚动 | 制造“忙但没进展”的反差 | 不出现或小于 15% | 是概念动效，不冒充真实截图 |
| 4–11s | 三张原帖证据卡依次拍入：2–4 小时、3 小时、thrashing | 证明痛点不是自创 | 0–20% | 卡片必须带来源名与 issue 编号 |

### 本条按时间采用的状态

`F 0–4s → E 4–11s → S 11–16s → F 16–22s → S 22–34s → E 34–51s → P 51–60s`

这不是为“丰富画面”而切换。每次状态变化都对应一次观众任务变化：被吸引、确认外部证据、听真实病例、看纠正冲突、理解机制、学习方法、接受行动。

严禁：

- 把完整 16:9 Codex 界面整体缩进 9:16；
- 同时展示侧栏、正文、右侧图片和人物；
- 用无关 B-roll 代替证据；
- 把 issue 用户报告升级成厂商已确认的普遍规律；
- 为了节奏把四段口播切成大量碎片，造成声音和人物断续。

### CTA

主 CTA：收藏下一条“五步外部审计演示”。

## 证据边界

- “1430 次执行、336 次等待、16 次压缩”是该会话的原始行为计数；它们本身不等于错误。
- “重新陈述 8 次”来自一个重复诉求簇，表示同类要求没有一次稳定落地，不表示八条文字完全相同。
- GitHub issue 是用户报告，不等于 OpenAI 或 Anthropic 已确认根因。
- Claude 官方只确认 autocompact thrashing 这一故障状态及恢复办法，不支持“所有压缩都会漂移”。
- 不能声称 Session Forensics 可以根治漂移；它能把活动、产物和目标之间的裂缝变成可审查证据。

## 发布实验

- 唯一变量：前 3 秒用“3 小时 0 改动”的失败画面，还是用“1430 次执行 ≠ 进展”的数字反差。
- 主指标：目标观众的 3 秒留存。
- 护栏：负面评论中“夸大 / 不真实”的比例、完整观看、收藏率。
- 观察：24 小时初判，7 天复核；两个版本的正文、时长、发布时间段和封面层级尽量保持一致。
- 成功条件：连续两次可比发布中同方向提升，且“夸大”类负面没有显著增加。小红书分帖并非随机实验，时间和分发仍是混杂因素。
