# 《它不是没干活，它是在认真空转》编导执行方案 V3

## 1. 内容任务与账号合同

- **目标观众：** 已经让 Codex / Claude Code / 其他 Coding Agent 连续工作 30 分钟以上，遇到过反复规划、压缩、验证循环或“界面一直动但目标产物不变”的创作者与开发者。
- **使用时刻：** 长任务正在运行、用户准备继续催促或继续追加规则之前。
- **需求证据：** 自有会话 `019ff003-c337-76e2-888e-81bbd6584076` 的可复核失败闭环，以及 Codex #27588、#31351、#37600、#14120、#5957 和 Claude Code 官方 troubleshooting 中已报告的相邻失败模式。它证明痛点存在，不证明普遍发生。
- **唯一 primary job：** 让观众学会用“目标产物是否发生可验证变化”区分活动量与目标进展。
- **账号持续价值：** 用真实 Agent 会话做“目标—操作—产物—纠正”的证据型复盘；不卖万能提示词，不把个案升级成普遍规律。
- **本条 endpoint：** 保存最后的止损问题，下一次长任务直接使用。当前不承诺下一集，不以“关注后续”延迟交付。

## 2. 标题、封面、首镜合同

- **标题：** `AI 最可怕的不是罢工，是认真空转`
- **封面主文案：** `认真工作 2 小时，一个文件没改`
- **封面来源角标：** `用户报告 · Codex #27588`
- **封面副文案：** `活动量 ≠ 目标闭合`
- **首镜：** 与封面、第一句使用同一个 #27588 证明对象，不混入 #31351 或本地 metrics。
- **结尾：** `过去 10 分钟，哪个目标产物真的变了？`

标题负责冲突，封面与首镜立即限定为“用户报告”；中段主动展示本地会话真实改过 39 个文件，避免让“认真空转”被理解成“所有活动都是零产出”。

## 3. 事实与证据边界

- #27588 支持：报告者称 2–4+ 小时仍未进入文件编辑；不支持普遍发生或已确认根因。
- #31351 支持：报告者称约 3 小时反复自动压缩、无实际进展；不支持零文件改动。只放发布说明，不进 60 秒主片。
- Claude 官方支持：Claude Code 有 `Autocompact is thrashing` 这一不同故障状态；不支持它与 Codex 个案具有共同根因。只放发布说明。
- 自有 session 支持：11,396 行、1,430 exec、336 wait、16 compaction、102 patch、39 files；重复诉求簇有 8 个 members，7 组相邻 pair verdict 为 restated。
- 自有 session 可推断：大量活动真实存在，但“手机上内容可读”的目标后来仍被指出没有解决。不能说“什么都没做”或“用户额外重复八遍”。

## 4. 真实计时口播

使用 macOS `Tingting` 中文语音、`190 words/min` 对八个完整语义段逐段生成 AIFF，并以 `ffprobe` 测得纯发声合计 **51.15 秒**。七个段间各预留约 0.35 秒，开头预留 0.5 秒，结尾保留 1 秒，代理总长约 **55.1 秒**。这只是自然节奏代理，不代替出镜者实录；正式剪辑前必须用一条不加速的真人连续 take 重新计时。若真人超过 60 秒，先删文案，不加速、不碎切。

| 段 | 定稿原声 | 代理实测 | 成片分配 |
|---|---|---:|---:|
| V1 | AI 最可怕的不是罢工，是认真工作两小时，一个文件都没改。 | 4.96s | 0.5–5.5s |
| V2 | 这不是段子。Codex 公开 issue 里，有人跑了两到四小时，反复读规则、压缩，仍没进入文件编辑。 | 7.99s | 5.85–13.85s |
| V3 | 我的剪辑任务也有一千四百三十次执行、三百三十六次等待、十六次压缩。 | 6.25s | 14.20–20.45s |
| V4 | 同类画面要求共有八次表达，七次相邻表达被判为重述。 | 4.73s | 20.80–25.55s |
| V5 | 但它也改过三十九个文件。所以问题不是没干活，而是活动量不等于目标闭合。 | 6.29s | 25.90–32.20s |

## 5. 逐段剪辑决策

母版 1080×1920；审片尺寸 360×640。八个原声段按完整语义保留。若不是一条连续 take，只在段间 0.35 秒停顿处切接口，并用上区证据覆盖人物接缝。

| 时间 | 原声 | 状态 | 上方内容/ROI | 人物与转场 | 屏幕验收 |
|---|---|---|---|---|---|
| 0.0–5.5 | V1 | F | `2–4+ 小时 / 仍未进入文件编辑 / 用户报告 · Codex #27588` | 人物隐藏；0.5s 静止后原声进入 | 来源 ≥12px；不得写 3 小时或混用本地数据 |
| 5.85–13.85 | V2 | E | `读规则 → 压缩 → 再读规则`，来源角标常驻 | 人物 24%，完整句不切脸；证据随三个动作替换 | 同时只读一个动作；不冒充真实 UI |
| 14.20–20.45 | V3 | S→E | `1,430 EXEC / 336 WAIT / 16 COMPACTION` | 人物 36%→24%，420ms 同缓动 | 每项标 `活动计数`，不是失败计数 |
| 20.80–25.55 | V4 | E | `8 次表达 / 7 组相邻重述` | 人物 24%，保持同一个 take | 必须同时出现 members / adjacent 的解释 |
| 25.90–32.20 | V5 | E | 先 `39 FILES CHANGED`，再出现 `活动量 ≠ 目标闭合` 与 `本案例判断` | 人物看向上区；180ms 对照切 | 明确“不是零工作”；字幕不遮反转 |
| 32.55–38.60 | V6 | S | `目标 / 工具 / 文件 / 用户纠正` 四节点逐词亮起 | 人物 36%，人物负责解释关系 | 不展示复杂 dashboard；一句一个主运动 |
| 38.95–48.15 | V7 | F→E | `目标：手机内容可读` → `物证：后来仍说录屏不可读` → `暂停新增 → 继续 / 分拆 / 停止` | 前两卡人物隐藏；动作卡人物 24% 回来 | 私有内容只用匿名转录；例外条件写 `外部等待/人工批准先核实` |
| 48.50–55.20 | V8+HOLD | P | `过去 10 分钟，哪个目标产物真的变了？` | 证据先停 200ms，人物 450ms 放大到 62%；末尾静止 1s | 可一眼截图；不承诺不存在的下一条 |

### 四态与剪辑纪律

- F=内容 100%；E=内容 76%/人物 24%；S=内容 64%/人物 36%；P=内容 38%/人物 62%。
- 人物永远保留真实矩形背景与圆角，不抠像；头顶 8–12%，下巴到底 ≥10%。
- 上区横屏全貌最多 0.5–0.8 秒，随后必须切语义 ROI；禁止把完整 16:9 桌面压成不可读小窗。
- 字幕位于上下边界，360 宽下 ≥16px，单行 10–16 汉字；来源角标 ≥12px。证据说明、字幕、人物嘴眼不得互相遮挡。
- 一句一个主运动；不得让证据、人物、字幕同时各自动画。

## 7. 生产、隐私与权利

当前状态：`DIRECTING_SPEC_CANDIDATE / PRODUCTION_BLOCKED`。

未解除的生产阻塞：真人连续口播原片、出镜与声音发布同意、会话最小转录脱敏、BGM/音效/字体许可、最终导出二次复核。处理规则：无法获得授权的外部页面与私有截图一律替换成自制事实卡；删除 session ID、绝对路径、用户名、邮箱、密钥、未发布项目、无关情绪和截图元数据；GitHub/官方材料只留最少摘录、来源与链接/编号；跨厂商不得暗示共同根因。

若无授权音乐，使用纯人声与原创轻提示音。发布前由第二位复核人只检查编码后的最终导出，确认遮挡仍有效；任何事实错误、隐私泄漏或厂商归因混淆都触发停止发布。

## 8. 单变量发布实验

实验变量明确定义为 **0–5.5 秒 opening proof package**，不是只换一张图。A/B 各自的声音、卡片和来源内部一致；5.85–55.20 秒完全相同。

| 包 | 0–5.5 秒原声 | 卡片 | 来源 |
|---|---|---|---|
| A 外部荒诞 | `AI 最可怕的不是罢工，是认真工作两小时，一个文件都没改。` | `2–4+ 小时 / 仍未进入文件编辑` | `用户报告 · Codex #27588` |
| B 本地反差 | `一个任务一千四百三十次执行，不代表它解决了你最在意的问题。`（同一代理实测 5.04s） | `1,430 EXEC / 目标后来仍未闭合` | `本地会话个案 · 活动计数` |

实验标题统一为较中性的 `Agent 一直在跑，为什么任务还是会偏？`，封面统一为 `活动量 ≠ 目标闭合`；因此实验与上方默认 A 版的传播标题/封面是不同的发布包，必须在实验日志中二选一，不能混用。唯一变化是 `0–5.5s` 的完整 opening proof package；`5.85–55.20s` 的正文画面与原声、总时长 ±1 秒、CTA、后段声轨、同星期与同 ±30 分钟窗口全部锁定。

- 主指标：后台 3 秒留存；分母为后台有效播放。
- 护栏：完播率、收藏/有效播放、主页访问/有效播放、以及“夸大/不真实/混淆厂商”负评占有效评论比例。
- 每版有效播放 ≥3,000；不足只记录方向。成功线：相对 3 秒留存 +10%，完播下降 ≤8%，负评率增加 ≤1 个百分点，两个可比批次方向一致。
- 两人独立编码评论，一条可多标签；发布窗口、封面或分发有偏离则记录，不能宣布胜出。小红书分帖非随机，结果只能写“该批次相关”。

## 9. 发布后复盘

依次检查入口、早理解、价值、信任和执行：观众是否认出痛点；能否复述“活动量不等于目标闭合”；是否保存最后的问题；是否质疑数字拼接或厂商混淆；成片是否真正在 360×640 下让内容可读且没有碎切人物。只修最差的一层。
