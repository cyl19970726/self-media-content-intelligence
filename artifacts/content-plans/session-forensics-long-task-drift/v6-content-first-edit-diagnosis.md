# Session Forensics V6：内容在上、人物在下的重剪诊断

## 结论

当前 V6 已经在形式上出现“上内容、下人物”，但还没有形成 AI 红发魔女式的**内容优先口播语言**。它更像一套 7 分多钟的课程型 PPT：卡片精致、信息完整，但每一镜承担的信息过多，人物过小且长期静止，真实产品操作被大量重新设计的信息图覆盖。

我们应该学习的是职责分配，而不是复制红发、配色或具体字幕：

- 上区只回答此刻唯一的知识问题；
- 下区人物提供连续口播、情绪和可信度；
- 信息越关键，人物越小；
- 判断、反转和结尾，人物重新变大；
- 真实界面只在它能证明操作或结果时出现。

## 当前 V6 的主要问题

### 1. 有上下分区，但没有做到“一句话一个证据”

现有卡片常常一次展示完整模型、三层审计或多个状态。手机观众还在读第一层，口播已经进入下一层。上区需要按口播逐项展开，而不是把整张框架图一直放着。

### 2. 画面面积没有等于信息优先级

当前多段人物长期只有约 20–25%，但上区并不总有足够密集的证据；因此出现“人物很小、上面却有大片空背景”的情况。人物缩小应该只发生在关键数据、真实操作和复杂关系出现时。

### 3. 人物虽然连续，但更像被塞在页面底部

人物窗口和上区卡片属于同一画面，却没有形成真正的对话关系：人物很少随着判断、反转、结论重新获得画面权重。结果是观众感到自己在听 PPT 配音，而不是在听一个人带着自己看证据。

### 4. 字幕、人物和证据形成三个竞争焦点

字幕目前经常压在人物窗口内，上方又有大段文字。观众需要同时读两套文案并看口型。字幕应该固定在两区交界或平台安全底区，只承担口播，不复述上区卡片。

### 5. 真实操作证据被重新设计的信息图替代

素材池已有：复制 Session ID、粘贴请求、发送、审计响应等真实聚焦录屏。新版应该让这些动作成为产品可用性的证据；信息图用来解释不可见的思想，不应覆盖所有真实 UI。

### 6. 最强案例被做成一张完整长图，而非叙事推进

40MB 案例的五个发现都挤在总图里。正确做法是先短暂展示总图建立来源，再按口播逐条切成：

- 调度大脑 → 进程保姆；
- Revision 增加 → 业务结论不变；
- 小改动 → 全量 Gate；
- 状态不物化 → 压缩后重推；
- Candidate → Accepted 的语义漂移。

每次只保留当前一条，其余退场。

### 7. 7m33s 的课程节奏不适合传播型口播

原内容完整，但存在大量解释、重复和产品边界扩展。必须先锁定新的 A-roll 语义顺序，再重排上区视觉；不能在当前 7m33s 时间线上继续堆更多卡片。

## 目标视觉状态

| 状态 | 上方内容 | 下方人物 | 用途 |
|---|---:|---:|---|
| 默认讲解 | 64–68% | 28–34% | 问题、简单关系、四步解释 |
| 证据主导 | 76–82% | 14–20% | 审计数字、真实 UI、五个发现 |
| 人物主导 | 35–45% | 45–55% | 钩子后的个人判断、反转、结论 |
| 全屏证据 | 90–100% | 0–10% | 1–2 秒总图、决定性数据或操作结果 |

人物固定在下方中间，用真实矩形背景，不抠像；不同状态只改变大小和上区面积，不让人物左右乱跳。

## 推荐的 60–75 秒结构

### 0–4s｜证据钩子

上区：`2,979 Exec / 约 1,868 Wait / 仅 16 Patch`，数字逐个出现；结论为 `项目大脑变成了进程保姆`。

人物：下方约 20%，只保留惊讶/判断反应。

### 4–12s｜问题与用户损失

上区：`看起来一直工作 ≠ 没有偏离目标`。

人物：扩大到 40–45%，亲自解释为什么人失去掌控。

### 12–19s｜失败解法

上区：执行 Session 内部画出 `执行 → 自审 → 新 Gate → 继续执行` 的闭环。

人物：约 30%。强调“让执行者自己审查自己，会把局部视角带进审查”。

### 19–27s｜核心思想

上区：Executor 与 Auditor 两列，箭头只显示 `执行历史 → 外部审计 → 纠偏报告`。

人物：约 30–33%。中心句：`不是让同一个 AI 更聪明，而是给它一个独立视角。`

### 27–45s｜真实案例

先用 1 秒全图建立来源，然后选择最强的三条：

1. 持续 Wait，调度大脑变进程保姆；
2. Revision 增加，业务结论不变；
3. 小改动触发全量 Gate。

上区 78–82%，人物 14–18%；每条约 5 秒，一条证据对应一句口播。

### 45–55s｜怎么使用

使用真实聚焦录屏，而非概念卡：复制 Session ID → 新会话粘贴请求 → 审计报告出现。

上区约 76%，人物约 20%；屏录只保留当前动作 ROI。

### 55–65s｜方法与闭环

把五步压成逐项激活：定位 → 量化 → Drill → 物证对质 → 回传。

随后只留一句：`GB 级会话 → KB 级证据 → 可执行纠偏`。

### 65–72s｜人物结论

人物扩大到 50–55%。上区只留：`长任务不是一直等，而是定期让另一个 Session 审计它。`

结尾不承诺“根治”，改为：`它不能替你保证结果，但能让偏离更早暴露。`

## 剪辑纪律

- 先完成 A-roll 结构确认，再放 Motion Graphics、真实操作、字幕和声音处理。
- 四段原始口播按完整语义段保留；只在段间或自然气口切，不按每个短句切脸。
- 完整总图只出现 1–2 秒；后面全部换成单焦点卡。
- 每个上区画面必须能回答“观众此刻应该看懂什么”，回答不出来就删除。
- 横屏 UI 不得整体缩进竖屏；只展示 Session ID、输入框、发送状态、报告结果等当前 ROI。
- 360×640 预览下，正文至少 16px、来源至少 12px；字幕不得压住嘴、眼和关键证据。
- 人物缩小时重新检查鱼缸边缘等背景杂物，不能因缩小重新露出无关环境。

## 当前正确的工作顺序

1. 从四段现有口播中确认 60–75 秒的最终语义稿；
2. 在 ChatCut 复制 V6，先只做 A-roll 结构版；
3. 用户确认“听起来完整、不碎”后，再重排内容上区；
4. 先放三段真实操作证据，再补解释型 Motion Graphics；
5. 最后做字幕、声画接口、360×640 与转场验收。
