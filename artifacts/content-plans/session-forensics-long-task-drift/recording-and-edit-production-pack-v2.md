# Session Forensics｜重录与剪辑制作包 V2

## 0. 成片决定

这次先制作一条 **95–110 秒的完整产品解释母版**，讲清楚：

1. 长任务为什么会失控；
2. 为什么让执行 Agent 自审仍可能失败；
3. Session Forensics 的核心思想；
4. 它为什么能发现执行 Agent 自己看不见的问题；
5. 40MB / 三天多 Agent 案例发现了什么；
6. 产品怎么使用；
7. 报告如何回传并周期复审。

母版成立后，再从同一批素材派生 45–60 秒传播版。不要在拍摄前同时追求两个时长，也不要把已经通过语义评审的“公开 issue 认真空转”短片和这条产品解释母版混成一个案例。

视觉语言学习 AI 红发魔女的功能分工，不复制人物设定或外观：

- 上方是当前观点所需要的内容、证据或操作；
- 下方人物维持表达连续性、情绪和信任；
- 一句口播只对应一个主要视觉证据；
- 证据越重要，上方越大；个人判断和结论出现时，人物重新变大。

## 1. 口播不录“一镜到底”，录 9 个完整语义段

“连续”指观众听到的思想连续，不要求相机文件只有一条。每段 8–18 秒，自身语义完整；段前、段后各留 1–2 秒安静余量。后期只在段落边界切，并用上方内容覆盖接口。

### B1｜证据钩子｜约 11 秒

一个 Agent 连续跑了三天，执行了两千九百七十九次，等待了一千八百多次。

我原本以为它很努力，审计后才发现，负责推进项目的大脑，已经变成了进程保姆。

### B2｜真正危险｜约 8 秒

长任务最危险的不是它停下来，而是它一直在工作，你却不知道它有没有偏离最初目标。

### B3｜错误解法｜约 11 秒

我们一开始让执行 Agent 自己审查自己。

结果它带着原来的局部视角继续审查，又给项目增加更多 Gate，反而进入另一个循环。

### B4｜核心思想｜约 10 秒

所以 Session Forensics 的核心，不是让同一个 AI 更聪明，而是再开一个独立 Session，把执行权和审计权分开。

### B5｜为什么它能做好审计｜约 16 秒

它会把一条会话拆成两条流：一条是 Agent 怎么解释自己，包括计划、总结和“已经完成”；另一条是物证，也就是它真正调用了什么工具、改了哪些文件、测试和失败是什么。

它不相信任何一条自我叙事，而是把两条流放在一起，专门寻找它们之间的裂缝。

### B6｜为什么必须是外部 Session｜约 10 秒

更关键的是，执行 Agent 的视野会被当前计划和上下文压缩限制。外部 Session 重新检查完整历史，才能发现跨阶段引用已经失效、目标已经漂移，却没有被当前计划察觉的问题。

### B7｜三条案例发现｜约 15 秒

它读完这条四十兆的会话记录后，发现三件事：

大量时间花在等待和轮询；版本号不断增加，业务结论没有变化；很小的代码改动，也会触发全量验证。

### B8｜怎么使用与形成动作｜约 13 秒

使用很简单：复制要审计的 Session ID，在新会话里调用 Session Forensics。

它会先把海量记录压成可检查的指标，再沿着裂缝有界下钻证据，最后给出继续、干预、升层或者停止的具体动作。

### B9｜产品闭环与结论｜约 10 秒

最后，它会把可执行的纠偏报告发回原 Session。长任务还可以每隔三小时复审一次。

它不能替你保证结果，但能让偏离更早暴露。

### 口播边界

- `2,979 Exec / 约 1,868 Wait / 16 Patch` 是案例活动结构，不代表所有活动都无效。
- “项目大脑变成进程保姆”是对大量等待与轮询的案例判断。
- “叙事流”只作为待质证的宣称，所有结论最终必须有工具调用、文件、测试、失败、耗时或用户纠正等物证支持。
- “外部 Session”不是泛泛的第二双眼睛，而是让审计者拥有全局工作集，重新检查跨阶段关系和已经失效的旧结论。
- 指标本身只说明发生了什么，不自动判定好坏；结论必须通过有界钻取回到具体证据。
- “不能替你保证结果”必须保留，避免把审计工具说成自动成功系统。
- 若真人自然说完超过 110 秒，先删重复解释，不加速，不把完整句切碎。

## 2. 提词器录法

### 设备位置

- 提词器文字必须尽量贴近镜头轴线。无分光镜时，把手机或平板紧贴镜头正下方，视线偏差尽量控制在 3–5 度内。
- 文字栏用窄列居中，避免眼球左右扫动。每行约 8–14 个汉字，每屏不超过 4 行。
- 字号调到距离相机 1–1.5 米仍不眯眼；关键词可换色，但不要整段高亮。

### 滚动方式

- 优先用遥控器、脚踏或轻触翻页，一段一页；不建议用固定速度自动滚完整篇。
- 每段先默读一次，再录两遍：A 版稳、B 版更有情绪。
- 眼睛先读一个短语，再对着镜头说出来；不要边扫描文字边发声。

### 节奏标记

- 逗号处正常换气；句号处停约 0.3–0.5 秒；段落末尾停 1–2 秒。
- 数字和英文术语前稍慢：`两千九百七十九次`、`Session Forensics`、`Session ID`。
- B1、B5、B9 各录一条更慢、更确定的备用版本，因为它们分别承担钩子、机制和结论。

### 连续性的真正来源

- 全部段落保持相同机位、焦段、曝光、白平衡、收音距离和坐姿。
- 每段开头先看镜头 1 秒再说，结尾说完后继续看镜头 2 秒。
- 不在一句话中间停机；忘词就从当前语义段的第一句重来。
- 每次开录先说 `B1 A`、`B1 B` 等场记，正式说话前停 2 秒，便于后期定位和删除。

## 3. 人物拍摄资产

### 必须拍

1. **9 段主口播 × 每段 2 take**：横屏 4K、30fps 优先；最终会裁成竖屏下方宽人物窗。
2. **10–15 秒环境底噪**：人不说话、不动，用于声轨修复。
3. **5 秒中性看镜头**：不说话，用作开头或结尾停留。
4. **3 组反应余量**，每组 3–5 秒：轻微怀疑、意识到问题、确定地点头；不要夸张表演。
5. **一句独立结尾备用**：`它不能保证结果，但能让偏离更早暴露。`

### 机位与画面

- 横屏中近景，镜头与眼睛齐平；头顶保留约 8–12%，胸口以上入画，肩线完整。
- 人物最好略偏画面一侧但不要贴边，给后期裁掉鱼缸边缘、椅子和杂物的空间。
- 锁定曝光、白平衡和对焦；不要让鱼缸反光或屏幕亮度改变脸部曝光。
- 背景可以保留个性，但需要安静：关掉会持续吸引视线的动态灯、电视或高亮屏幕。

### 收音

- 声音优先于画质：领夹麦或距嘴较近的指向麦；距离全程一致。
- 关闭空调、风扇、手机震动和系统提示；在正式录制前拍 15 秒试听。
- 不要直接使用过强降噪；后期先用保守强度测试，确保不出现水下感、金属感或吞字。

### 文件命名

- `SF_B01_A.mp4`、`SF_B01_B.mp4`……`SF_B09_B.mp4`
- `SF_ROOMTONE.wav` 或视频原文件
- `SF_REACTION_SKEPTICAL.mp4`
- `SF_REACTION_REALIZE.mp4`
- `SF_REACTION_NOD.mp4`
- `SF_END_ALT.mp4`

为了让产品“能怎么用”不只停留在概念卡，建议重新录一条干净、连续、1440p 以上的操作母带：

### C. 必须准备的证据卡

由剪辑端制作，不要求你拍：

- `23,417 条记录 / 19 次 Compaction` 来源卡；

- `调度大脑 → 进程保姆` 状态变化卡；
- `Revision 增加 / 业务结论不变` 对照卡；
- `小改动 → 全量 Gate` 因果卡；
- `执行 Session / 外部审计 Session` 双角色卡；
- `叙事流 / 物证流` 双流对质卡；
- `宣称 ↔ 动作 / 引用 ↔ 当前事实` 两类裂缝卡；
- `局部计划 → 上下文压缩 → 全局关系不可见` 视野收窄卡；
- `GB 级物证 → KB 级指标 → 有界下钻` 上下文边界卡；
- `继续 / 干预 / 升层 / 停止` 动作终点卡；
- `定位 → 量化 → 有界下钻 → 物证对质 → 回传` 五步卡；
- `GB 会话 → KB 证据 → 可执行纠偏` 压缩链。

### D. 隐私与权利

- Session ID、用户名、邮箱、绝对路径、密钥、未发布项目名全部脱敏。
- 报告截图只留支撑当前观点的最小区域。
- 外部页面如无明确使用许可，改成自制来源卡，不直接长时间展示页面。
- 字体、背景音乐和音效必须有可发布许可；没有授权音乐时，宁可使用纯人声加原创轻提示音。

| 10–18s | B2 | 人物主导 | 只留“持续工作 ≠ 方向正确” | 约 50%，让观众先相信这个判断 |

| 38–56s | B5 | 内容主导 | 左侧叙事流、右侧物证流；一条宣称与一条真实动作发生冲突，裂缝被高亮 | 18–22% |
| 56–68s | B6 | 内容主导 | 局部计划与 compaction 遮住跨阶段关系；外部 Session 拉回完整时间轴 | 18–22% |
| 68–83s | B7 | 全屏来源 1 秒 → 证据主导 | Wait、Revision、Gate 三张单焦点卡依次出现 | 14–18%，必要时短暂隐藏 |

布局默认是内容约 2/3、人物约 1/3，但不是固定模板：

- 简单解释：内容 62–68%，人物 28–34%；
- 关键数据、界面、流程：内容 76–82%，人物 14–20%；
- 判断和结论：人物 45–58%；
- 决定性证据可短暂全屏，人物退场 1–2 秒。

人物固定在下方中间，只改变面积，不左右跳动；每次缩放都要重新检查人物裁切和背景杂物。

## 6. 正式剪辑过程

### 阶段 1｜先锁口播 A-roll

1. 导入所有 B1–B9 take；
2. 每段选一条最完整、最自然的版本；
3. 只删除错误重录、明显口头停顿和无意义空白；
4. 保留句间 0.3–0.5 秒呼吸；
5. 段落接口用 0.3–0.5 秒自然间隔连接；
6. 完整听一遍，检查逻辑是否仍为“问题 → 错误解法 → 角色分离 → 双流对质 → 全局重验 → 案例 → 使用 → 动作闭环”。

**检查点 1：** 先只听声音和看人物，确认不碎、不赶、没有语义跳跃。A-roll 未确认前，不开始大规模做上方视觉。

### 阶段 2｜建立四种布局状态

先做人物主导、默认讲解、证据主导、全屏证据四种模板，统一背景、圆角、边缘高光、阴影和字幕安全区。用 360×640 尺寸检查，不以桌面预览“看得见”为准。

**检查点 2：** 用真实人物素材验收四个静态帧，尤其检查脸、头顶、下巴、鱼缸边缘和字幕位置。

### 阶段 3｜先放真实证据，再做解释动画

1. 先放复制 ID、粘贴请求、报告出现、回传纠偏等真实 ROI 录屏；
2. 案例总图只出现 1–2 秒；
3. 再把 Wait、Revision、Gate 拆成单焦点 Motion Graphics；
4. 心智模型动画必须先出现“叙事流”和“物证流”，再出现裂缝；不能一上来展示完整复杂框架；
5. 每个语义段只设一个主要运动，不让字幕、人物和证据同时抢动。

**检查点 3：** 静音看一遍，观众是否能仅凭上方画面知道当前在说哪一件事。

### 阶段 4｜字幕、声音与转场

1. 字幕固定在上下区交界或稳定安全区；
2. 一行约 10–16 个汉字，避免复述上方卡片；
3. 对每条人物源分别试听保守降噪，保留未处理版本；
4. 所有语音硬切完成后统一做微交叉淡化，避免爆音；
5. 背景音乐只负责连续性，音量低于人声，不用“科技感”掩盖信息；
6. 关键词切换尽量在口播说出后 8–15 帧内响应，普通缩放/替换约 12–24 帧。

### 阶段 5｜手机验收与导出

至少检查：开头数字、B3 自审循环、B5 双流裂缝、B6 全局重验、B7 三条案例、B8 真实操作和 B9 结尾等稳定帧，以及每个布局切换的前/中/后三帧。

拒绝以下情况：

- 上方同时有两个同等重要的知识焦点；
- 整张横屏 UI 缩小后不可读；
- 人物一直保持同一大小，信息优先级没有画面变化；
- 字幕压住嘴、眼睛、按钮或关键数字；
- 证据卡的字在 360×640 下需要停下来眯眼看；
- 录屏包含未脱敏信息；
- 成片为了卡时长而加速人声或切碎完整句。

## 7. 谁准备什么

### 你需要准备

- 按 B1–B9 录制的 18 条主口播 take；
- 环境底噪、三组反应、备用结尾；
- 若现有录屏不够清楚，补录一条连续的产品操作母带；
- 确认可展示的案例数据、界面范围和需要遮挡的信息；
- 最终确认出镜、声音、字体、音乐及外部页面的发布权利。

### 剪辑端负责

- 选择 take、清理 A-roll、保持语义连续；
- 把现有 40MB 总图拆成单焦点证据；
- 对真实屏录做手机可读 ROI 重构；
- 制作四种布局、Motion Graphics、字幕和音频处理；
- 完成 360×640 验收、隐私复核和最终导出；
- 从 95–110 秒母版派生 45–60 秒传播版，而不是让你重新录一遍。
