# 人类最强编导全量研究与 Deep Content Director 交付报告

完成时间：2026-08-16（Asia/Shanghai）  
状态：研究、保留集盲测、Skill 构建、静态攻击测试和三项前向测试均完成。

## 1. 最终结论

这批内容真正可迁移的，不是“最强”称号、面罩、毒舌或收入背书，而是一套内容决策闭环：

`账号承诺 → 内容组合 → 单条任务 → 需求证据 → 选题假设 → 点击/关注合同 → 论证或故事 → 证明链 → 画面功能 → 发布实验 → 分层复盘 → 规则修订`

关于“给自己一个牛逼人设是不是更容易火”，答案是：它可能放大首屏注意，也同时放大质疑与声誉风险；19 条公开视频不能证明它独立导致播放、涨粉或成交。可持续人设更接近：

`身份清晰 × 稳定符号 × 范围明确的证明 × 价值立场 × 连续兑现 × 用户相关性`

因此，我们不复制“人类最强”、面罩、收入排名或他人案例所有权。我们把高位人设改写为可验收的工作身份，并用连续交付建立信任。

## 3. 对我们起号最有用的策略

### 账号承诺

推荐工作身份：**AI 工作验收员**。

起号假设：帮助被 AI 工具碎片和“自动爆款”话术困住的独立创作者，把一个真实内容任务做成可核对、可交接、可复盘的交付物。

这是待验证的承诺，不是市场事实。现阶段我们有工具演示、拉片、结构化报告和制作过程证据，但没有可公开验证的涨粉、收入或大客户成绩，因此先证明工作完整度，不建立结果领先型人设。

### 身份系统

- 身份词：AI 工作验收员。
- 态度：冷静、具体、先展示再结论；不神化工具，也不嘲讽不会用工具的人。
- 固定语言：看见了什么 / 哪句是推断 / 还不知道什么 / 下一步交什么。
- 固定视觉：事实、推断、未知、下一步四张工作卡。
- 固定结构：交付物先行 → 验收标准 → 操作或证据 → 人机边界 → 下一件工作。
- 禁区：最强称号、面罩复刻、毒舌复刻、收入截图、客户 logo、未经核验的效率数字、自动爆款承诺。

### 两个互补系列

1. **7 天，AI 把一条内容做完**：每天推进同一案例的一个工作阶段，从拉片、选题、脚本、镜头、粗剪、包装实验到复盘交付。
2. **同一任务，工具怎么选**：相同输入与验收表，比较 Codex、Flova 等工具在不同任务下的上下文要求、可验收性、人工修订量和交接适配；输出条件式选择卡，不做工具总榜。

首集建议：**《别让 AI 替你猜爆款：先检查这 4 样东西》**。主任务是合格触达，守门任务是信任不下降；展示一份脱敏交付物和四项验收标准，不展示第三方未闭权素材，也不把工作完成度说成爆款因果。

### 7 天发布顺序

1. 验收一次 AI 拉片：字幕、画面证据、时间码、剪辑决定。
2. 拉片到原创选题：比较三种真正不同的受众/承诺/证明组合。
3. 写可拍脚本：每个 beat 标注认知任务。
4. 一人手机镜头表：时长、功能、证据责任与替代镜头。
5. 素材到粗剪：keep / compress / remove 与目标时长。
6. 包装不靠猜：标题、封面、首帧闭合，只测试一个 opening 变量。
7. 交付包与复盘：展示七个工作件、返工和下一项唯一改动。

## 4. 数据与复盘方法

每条内容只能有一个主任务、至多一个守门任务。不要用点赞统一评价所有内容。

- 合格触达：首屏停留、到达首个完整解释的比例；不可得时记录代理指标及限制。
- 搜索/收藏：搜索入口、后窗触达、收藏与可回查行为；不把收藏直接叫复看。
- 关注承接：有效观看后主页/关注动作；后台不可得就保持 unknown。
- 信任：观众能否正确复述证明对象、是否出现“保证爆款/涨粉”的误解。
- 生产：单集制作时间、返工次数、权利处理时间和未完成项。
- 系列：跨集/目录行为和下一集意图；单条热度不等于系列成立。

第一次实验只变 opening：结果先行 vs 问题先行。锁定时长、四卡视觉、边界说明、CTA、时段、无投流与互动操纵。小样本只做方向性学习，不宣布平台规律。

复盘顺序：执行偏差 → 分发/时延 → 封面标题 → 前段留存 → 兑现与理解 → 关注/主页承接 → 目标动作 → 商业结果 → 负反馈/合规。最后只选择下一版的一个主变量。

## 5. 新 Skill 怎样使用

Skill 路径：`/Users/hhh0x/.codex/skills/deep-content-director/`

它支持五种模式：

- `account`：定位、身份承诺、内容组合、系列和节奏；
- `single`：单条从 brief、脚本、镜头到实验；
- `series`：跨集未来价值、角色和续期规则；
- `research`：从帖子/博主研究迁移成原创策略；
- `review`：诊断现有稿件、成片或表现，并给下一版唯一改动。

推荐调用方式：

> 用 deep-content-director，模式 account。基于我现有的工具演示、拉片报告和一人手机制作约束，设计 30 天小红书起号方案；把事实、推断、假设和未知分开，并给首集完整 JSON 与可读 brief。

> 用 deep-content-director，模式 research。先用 video-content-reconstruction 还原这组帖子，再做跨帖对比；不要从点赞推因果，最后给三个原创迁移候选和一个单变量实验。

> 用 deep-content-director，模式 review。对这条已发布内容按漏斗层诊断，给 keep/compress/remove、证据、下一版唯一变量和仍需的后台数据。

结构化输出必须先过 validator；`completionReady=true` 只表示结构候选完成，仍必须由独立 reviewer 通过 G0–G7。作者不能自评语义 ready。

## 7. 仍然不知道什么

- 公开数据无法回答作者历史异常、留存、主页访问、净增粉、投流、成交或真实制作成本。
- 19 条内容来自一个博主，稳定原则虽通过五种保留类型测试，仍需用我们自己的发布数据继续修订。
