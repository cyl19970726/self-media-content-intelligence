# 独立审计：688ab6260000000022020d3e

## 结论

**不通过，需纠正后再用。** 视频确实展示了 Runway 的角色表演驱动界面和多种动态角色样例，但存在一个关键事实错误：口播和大字字幕都称其为 **Act One**，实际工作区和结果页却明确标为 **Act‑Two**。后半段“一句话 P 图改图、换表情、改动作、变风格”的口播也没有对应操作或前后对比，和画面中的 Act‑Two 动画结果并不匹配。

审计仅使用指定 MP4、SRT 和新 evidence pack；未读取 Skill、candidate 或旧报告。

## 一、产品与界面事实

### 1. Act One 口播与 Act‑Two 界面直接冲突

- 8.66–10.79 秒：SRT 与画面大字字幕均为“这就是 runway 的黑科技 act one”。
- 9.0–10.5 秒：Runway 工作区左下方模式按钮清楚写着 **Act‑Two**（DENSE-0013～0015）。
- 约 15 秒：生成结果页左上方再次显示 **Act‑Two**。

因此，本片实际展示的是 Act‑Two。这里不是名称模糊或推测，而是口播/字幕与可见 UI 的直接矛盾。

### 2. “Gen‑4: Now for Image and Video” 是宣传卡，不是当前模式

9.0–10.5 秒右侧可见标题 **“Gen‑4: Now for Image and Video”** 及 “Try it now”。同一画面左侧仍是 Performance/Character 两栏，底部模式为 Act‑Two。它是并列的产品宣传区域，片中没有点击 “Try it now”、切换 Gen‑4 或展示 Gen‑4 工作流，不能据此把当前功能认定为 Gen‑4。

### 3. 双输入与 Generate 按钮真实可见

- Performance：**Add driving performance**；说明为 **Use voice, gestures and facial expressions up to 30s**；可 **Record** 或 **Select asset**（DENSE-0016～0017，约 11.5 秒）。
- Character：**Choose your character**；说明为 **Drop image or video**；可 **Select asset**（DENSE-0018～0019，约 13.0–13.8 秒）。
- 下方可见 **Generate** 按钮（DENSE-0013～0015）。
- 14.1 秒后出现带 Act‑Two 标记的 Mario-like 角色播放器结果。

所以“一个驱动表演素材 + 一个角色素材 + Generate”的结构成立，但片中没有展示选素材、点击 Generate、等待和完成的完整链路。Character 也并非只能传图片，它明确支持 image or video；Performance 也可直接录制，并非只能上传视频。

## 二、角色范围与样例分组

片中样例可以按可见风格分为：

| 分组 | 可见样例 | 证据 |
|---|---|---|
| 真人/电影感 likeness | 魔法学校女生式角色、苍白电影反派式角色 | DENSE-0001～0003；0008～0010 |
| 玩偶/风格化 3D | 时尚玩偶式角色、Mario-like 角色 | DENSE-0004～0005；0011～0012；0020～0022 |
| 2D 动漫 | 西装动漫女性、粉发忍者式动漫女性 | DENSE-0006～0007；0023～0031 |

这些精选样例确实覆盖真人感、3D 和 2D 动漫，能够支持“可驱动多类角色素材”的弱结论；不能支持“任意演员”的绝对范围。片中没有失败样例、遮挡/侧脸/多人/复杂动作测试、输入限制或 UI 中的 “any character” 保证。

## 三、连续动作、同步与因果

### 可确认

- 0–8.6 秒的分屏中，主持人与上方角色都出现持续的嘴部、表情和手势变化；例如双手抬起、双食指指向和表情切换。
- 16.5–22.347 秒，粉发动漫角色在近 6 秒内连续改变嘴型、头部状态和双手姿态（DENSE-0023～0031）。这足以确认“画面中存在连续动画”。

### 不可确认

- 分屏是编辑后并置，片中没有加载并播放原始 driving performance，也没有原始表演与结果的逐帧对照，因此不能证明这些输出确由下方主持人的动作生成。
- 没有隔离的成片角色语音，也没有逐帧口型对照，不能证明“口型和动作都准确同步”。
- UI 明示驱动因素是 **voice, gestures and facial expressions**，主持人也在做大量手势，所以“靠一张嘴驱动”反而与可见 UI 和画面不一致。

更准确的说法应是：“可用一段表演素材中的声音、表情和手势驱动角色；样例展示了连续动作效果。”

## 四、时间与“一键/一句话”范围

### “几分钟”没有计时证据

约 13.8 秒还是 Character 选择区，14.1 秒已跳切到完成的结果播放器。片中没有 Generate 点击、加载状态、起止时间或不间断等待。播放器的 “0:19” 是成片播放时长，不是生成耗时。因此，“几分钟生成”在本片中未被验证。

### 一句话 P 图改图没有画面支持

16.27–22.476 秒口播/SRT 称“一句话就可以批图改图，比如给图片换表情、改动作、变风格”。该时段全程只有粉发动漫角色连续动作：

- 没有输入一句话或填写 prompt；
- 没有图片前后对比；
- 没有分别展示换表情、改动作、变风格；
- 先前虽可见 Prompt 标签，但没有任何 prompt 内容或 prompt 驱动操作。

因此，这段口播像是在描述另一项图片编辑能力，不能用当前 Act‑Two 画面作证。可见一个 Generate 按钮，也不等于双素材流程能“一键完成”或“一句话改图”。

## 五、SRT 与画面字幕冲突

| 时段 | 提供的 SRT | 画面硬字幕 | 判定 |
|---|---|---|---|
| 10.80–约 13.8 秒 | “再贴一张你想**祛痘**的图” | “再贴一张你想**驱动**的图” | SRT 误识别；语境和 UI 支持“驱动” |
| 约 13.8–16.26 秒 | “让**土里**的人活过来” | “让**图里**的人活过来” | SRT 误识别；画面支持“图里” |
| 8.66–10.79 秒 | “act one” | “act one” | 两者一致，但都与可见 **Act‑Two** UI 冲突，属于内容事实错误 |
| 16.27–22.476 秒 | “批图改图” | 无可见硬字幕 | 可能是 “P图” 同音误识别，但仅凭现有画面无法定案，应回听原始音频 |

建议至少先把 SRT 改为“想驱动的图”“图里的人”，再对“批图/P图”做人工听校；Act One 则需同时改口播、硬字幕和相关文案。

## 六、身份与授权

视频使用了多组高度可识别的影视/游戏/动漫角色式素材，以及可能带演员 likeness 的真人感素材。但 22.467 秒内没有出现：

- 真实人物同意或身份授权；
- 角色/IP 许可、素材来源或版权说明；
- 冒充/误导提示；
- 上传资产的权利确认流程。

这不能直接证明侵权，但也完全不能证明已授权。内容不应暗示“任意演员/角色”天然都可以合法使用；发布前应保留素材来源、许可或本人同意记录，并加权利边界提示。

## 七、关键负证据

片中没有展示：

1. 选择/上传 driving asset；
2. 选择/上传 character asset；
3. 点击 Generate 与生成进度；
4. “几分钟”耗时的计时依据；
5. 原始表演与结果逐帧对照；
6. 一句话 prompt 和图片编辑前后对比；
7. 换表情、改动作、变风格的独立演示；
8. 失败案例、输入边界或质量限制；
9. 人物/角色的许可、同意或素材 provenance。

## 必改项

1. 将口播和大字字幕中的 **Act One** 改为 **Act‑Two**，或更换为真正的 Act-One 操作画面。
2. SRT 将“想祛痘的图”改为“想驱动的图”，“土里的人”改为“图里的人”；回听确认“批图/P图”。
3. 删除或重拍“一句话 P 图改图”段落，必须出现 prompt、操作和前后对比。
4. 把“任意演员”“靠一张嘴”收窄为与 UI 和样例一致的范围。
5. 不把 Gen‑4 宣传卡写成当前使用的模型/模式。
6. 对可识别真人 likeness 和受保护角色增加授权、许可与素材来源保障。
