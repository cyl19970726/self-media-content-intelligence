# 《GPT4不香了🥹国产千问2，强大好用！》内容还原

## 一句话结论

这条视频不是一次“Qwen2 对 GPT-4 的实测胜负”。它是一条从“国产 AI 能否碾压 GPT-4”的强钩子出发，借 Qwen2 产品页、Qwen2-72B 对 Llama 3 等开源模型的榜单截图、两组编辑过的聊天画面和行业帖文，最终把观众引向“别再花冤枉钱，改用国产开源模型，并在评论区领取我打包的 Qwen2”的推荐视频。

真正被画面直接比较的是 Qwen2 与 Llama 3，而不是 GPT-4；GPT-4 没有出现同题回答、分数、版本、价格、速度或成本基线。因此，视频能支持“Qwen2 值得关注和亲自测试”，不能支持“Qwen2 已被该视频证明全面替代 GPT-4”。

## 视频的论证路线

### 1. 先把问题抬到 GPT-4

开场卡写的是“国产AI碾压GPT4? 学霸级模型免费用!”（00:00–00:03）。旁白又借一段舞台访谈画面，归因称黄仁勋赞扬 Meta 开源模型，并主张大模型应当开源（00:00–00:04）。但画面没有标注原始采访来源、日期和逐字引语，所以这里是作者的权威背书框架，不是可核验的原始引用。

随后作者否定“美国一开源，我们才有资源”的依附叙事，提出“如今大模型格局早已不是美国独霸，国产 Qwen2 才是炙手可热的开源模型”（00:04–00:16）。

### 2. 给出 Qwen2 的产品身份和规格

作者将它称为“来自阿里云的通义千问开源大模型”（00:16–00:19）；画面同时展示 Qwen2 的 logo、仓库/readme 和模型卡。

这里有两个不能互相覆盖的可见口径。约 00:16.5 的家族页面明确写的是五个尺寸：0.5B、1.5B、7B、57B-A14B、72B，并同时列出 Qwen2-72B-Instruct、Qwen2-72B 等不同变体。随后 00:22–00:28 的规格卡只展示四列：

- 用 29 种语言数据训练，包括英语和中文；
- 四个规格列：0.5B、1.5B、7B、72B；
- 0.5B、1.5B 的上下文为 32K；
- 7B、72B 的上下文为 128K。

旁白只突出“72B 版本 128K 上下文”，但画面实际还把 7B 列为 128K。57B-A14B 为什么出现在五尺寸家族页、却不在四列规格卡里，视频没有解释，因此不能擅自把它删掉，也不能把四列表的规格套给它。这说明“Qwen2”是一个模型家族，五尺寸目录、四列规格卡、Qwen2-72B、Qwen2-72B-Instruct 和后面的 demo 模型标签不能混成同一个身份。

### 3. 把“规格强”推进到“全面碾压 Llama 3”

作者声称 Qwen2 擅长多模态处理、多语言理解、逻辑推理和代码生成，并“全面碾压 Meta 的开源模型 Llama 3”（00:27.6–00:34.5）。

画面实际有两张不同规模的表，不能跨表拼接：

- 72B 表：Qwen2-72B-Instruct、Llama3-70B-Instruct、Qwen1.5-72B-Chat；
- 小模型表：Qwen2-7B-Instruct、Llama3-8B-Instruct、GLM4-9B-Chat。

行名包括 AlignBench、MT-Bench、MMLU、GSM8K、MATH、HumanEval、MBPP 等，另外还有代码语言雷达图和 HungaryExam、MathBench-A、GaoKao2023 等数学/考试图表。

而且 72B 表内部就有两个直接反例：MBPP 是 Qwen2 80.2、Llama 3 82.3；GSM8K 是 Qwen2 91.1、Llama 3 93.0，均由 Llama3-70B-Instruct 高于 Qwen2-72B-Instruct。因此画面不是“还不足以证明全面碾压”，而是已经直接否定了“所有项目全面胜出”这一字面范围。

需要特别避免一个跨行误读：小模型表的 HumanEval 是 Qwen2-7B 79.9、Llama3-8B 62.2、GLM4-9B 71.8；82.3 属于上方 72B 表的 MBPP，不是 Llama 3 的 HumanEval 分数，所以 HumanEval 不能再算第三个 Llama 胜项。

除此之外，视频仍没有给出榜单完整来源、测试日期、提示词、硬件、统计误差、是否同一评测条件，也没有展示多模态输入输出。准确结论是：部分可见项目支持 Qwen2 的优势，但 MBPP、GSM8K 构成直接反例，评测方法和外部有效性仍未知。

更关键的是：这些表里没有 GPT-4 列。标题里的 GPT-4 对手，到这里仍没有进入同场测试。

### 4. 一个容易被漏掉的许可证条件

在约 00:32.4–00:34.7 的短暂画面里，英文/中文说明写明：除 Qwen2 72B（instruct 和 base）外，其他模型获得 Apache 2.0 许可；Qwen2 72B 仍使用原有的 Qianwen License。

这条可见限定直接影响视频“免费国产开源错不了”的适用范围，尤其作者恰好重点推荐 72B。视频没有解释 Qianwen License 的具体权利、限制或商用条件，因此不能仅凭“开源/免费”的口号推断 72B 与 Apache 2.0 模型完全等价。

### 5. 行业背书和开发者使用

00:34.8–00:38.5 插入了标为 `clem @ClementDelangue` 的帖文。可见正文称为了新的 Open LLM Leaderboard，用 300 台 H100 重跑 MMLU-Pro 等评估，并称“Qwen 72B is the king”。但同一帖文也带有三条重要边界：旧评估对新模型已太容易；AI 开发者可能过度针对主要评测优化、牺牲其他表现；更大不一定更聪明。

接下来又出现有关 Qwen2-72B 排名的帖子、开发界面和一张猫的插图，作者据此声称“顶尖权威人士都心服口服”“海外开发者都在用 Qwen2 搭建应用”（00:34.5–00:42.5）。这些素材能证明视频展示了若干正面案例，但不能证明行业普遍共识、实际采用规模、生产部署数量，也不能证明猫图是这次画面里连续生成出来的结果。

## 视频实际展示了哪些测试任务和结果

### 任务一：讲一个笑话

在 Hugging Face Spaces 页面 `Xenova/webgpu-chat-qwen2` 中，历史对话包含用户提示 `Tell me a joke`，回答是一则“番茄为什么变红——因为看见沙拉在 dressing”的英文双关笑话（约 00:50.7–00:55.6）。

这能证明画面里存在一个可读的文本回答，但没有幽默质量评分，也无法从剪辑证明它是在拍摄中完整实时生成。

### 任务二：写斐波那契数列的 Python 代码

同一页面的提示是：`Write python code for fib(n) to compute the nth Fibonacci number.`（约 00:51.5）。随后 UI 出现加载/流式状态，并显示一个递归函数：`fibonacci(n)`，包含 `n <= 1` 的基例和 `fibonacci(n-1) + fibonacci(n-2)`，后面还能看到 `Test cases` 标题（约 00:53–00:55.4）。

画面结果是“生成了代码文本”，不是“代码已验证成功”：视频没有运行按钮、控制台结果、单元测试通过记录、复杂度说明，也没有 GPT-4 用同题生成的对照结果。这个片段最多证明该 demo 能产出一段看起来相关的递归 Python 代码。

### 任务三：用简单语言解释期权交易

随后出现一个深色双栏对照页面（约 00:55.6–01:00.3），模型标签是 `llama3:70b` 和 `qwen2:72b`，共同提示为：

> Explain options trading in simple terms if I'm familiar with buying and selling stocks.

左栏 Llama 3 从“期权是给买方权利而非义务的合同”讲起，并用了演唱会门票类比；右栏 Qwen2 从“对股票未来价格下注但比直接买卖更灵活”讲起，并继续解释 call/put。

视频没有标出哪个回答胜出，也没有人工评分、正确性检查、速度、token 成本或一致的生成参数。这个画面展示了“同题双回答”，没有展示“Qwen2 赢了”。而且这里的对手仍是 Llama 3，不是 GPT-4。

## GPT-4/OpenAI 比较到底成立到哪一步

作者在 00:42.5–00:46.3 把 OpenAI 描述为“一直不 open、傲慢和昂贵”，并说大约半年前还会推荐 GPT-4，但现在建议大家“别去花冤枉钱，直接用免费的国产开源”（00:46.3–00:55.6）。

这是一个清楚的个人推荐变化，但视频没有交代：

- GPT-4 的具体版本或产品形态；
- 付费套餐和实际价格；
- 与 Qwen2 对照的相同任务、提示词和输出；
- 响应速度、上下文利用、稳定性、安全性或工具能力；
- 本地跑 Qwen2 尤其 72B 所需的硬件、量化、显存、电费或托管成本。

因此，“OpenAI 昂贵”和“Qwen2 免费”是作者的价值判断/推荐，不是视频完成的总拥有成本比较。“模型权重或代码可获取”也不自动等于“实际推理零成本”。

## 结尾行动与风险边界

作者最后预测，开源路线继续深化后，大家还能“白嫖更强大的模型”（00:55.6–01:00.4）；随后说“Qwen2我已经打包好了，评论区安排”（01:00.4–01:03.7）。

这条 CTA 只明确了一个动作：去评论区表达需要。完整视频没有展示包内包含什么、由谁托管、是否来自官方、是否经过安全检查、对应哪个尺寸/量化、适用许可证、下载链接、账号/地区要求、运行环境、费用或后续支持。

非语音音轨另外做了有界机器语义听检，而不再把振幅检测当成“已听过”：连续窗口中，00:00–01:03.7 的每个窗口都把 Music 判为前两位语义标签，支持旁白下方存在持续的背景音乐床；22–24 秒还集中出现一个 ding 类短促转场/强调声。32–56 秒里机器偶发给出 camera、gunshot、chopping 等低或不稳定标签，这些没有被当作真实事件采纳。音乐的具体曲目、类型、来源和版权仍未知。

从 01:03.689 左右起，语义窗口以 Silence 为主，并与 -45 dB 振幅检测的长静音边界一致，持续到结尾；画面大部分时间为黑屏，约 01:17.5 后出现一张居中的 Qwen2 规格卡，重复前面的家族规格信息。它没有补上下载或使用边界。

## 证据约束下的行动建议

如果只根据这条视频做决定，最稳妥的动作不是直接接受“全面替代 GPT-4”，而是把 Qwen2 放进候选名单后完成五步核对：

1. 明确你要测的是 Qwen2 的哪个尺寸、base 还是 instruct、是否量化，以及 demo 页面实际调用的 checkpoint。
2. 读取对应许可证；尤其不要把 72B 自动当成 Apache 2.0，因为视频自己展示了 Qianwen License 限定。
3. 估算本地或云端推理的显存、算力、部署和持续费用，不把“可下载/开源”直接等同于“零成本”。
4. 用自己的真实任务做同提示词、同评分规则的 Qwen2/Llama 3/GPT-4 对照，至少检查正确性、稳定性、速度和成本。
5. 优先从官方仓库/模型页获取资源；对评论区转交的“打包版”先确认内容、哈希、许可证和来源，再决定是否运行。
