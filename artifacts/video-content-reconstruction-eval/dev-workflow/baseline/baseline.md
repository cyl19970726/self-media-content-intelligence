# 用 AI 在 3 小时内做一款乙女文字游戏：视频完整总结

这段约 1 分 51 秒的视频演示了一个“不会写代码也能做文字游戏”的开发流程。作者展示的成品是一款都市职场题材的乙女文字游戏：女主被大厂裁员后，在生存压力与多位男性角色之间推进剧情。作者称自己全程没有手写代码，约 3 小时完成原型，并把主要开发需求整理成了可复用的提示词模板。

视频的核心并不是让一个聊天模型直接吐出完整游戏，而是让具备代理能力的 AI 编程工具接管开发工作：它能理解需求、在项目文件中写代码、查找素材、运行项目，并根据反馈继续修改。

## 视频讲了什么

第一步是准备 AI 开发环境。作者使用 Claude Code，并把 Kimi K2 Thinking 的 API 配置给它。大致流程是：如果本机没有 Claude Code，先通过终端安装；不想自己配置 Claude Code 的人，也可以考虑直接安装 Kimi CLI。随后前往 Kimi 开发者平台获取 API Key，把它填入作者给出的环境配置命令，再在终端执行。配置完成后先做一次测试，确认 Claude Code 可以调用模型并正常运行。

第二步是把游戏需求一次性讲清楚。作者的提示词不只写了一个故事梗概，而是同时描述了游戏世界观、技术方案、主角设定、男性角色、剧情与玩法、页面和交互、核心数值，以及希望 AI 按什么步骤开发。画面中的成品还包含精力、情绪、压力、金钱、事业、社交等状态值。AI 收到这些信息后，很快建立了可运行的游戏框架、文本内容和基础界面。

第三步是补齐美术资产。游戏框架生成后，文本已经有了，但人物立绘和其他图片仍然缺失。作者先自行生成或准备角色图片，把素材集中放进项目文件夹，再告诉 Claude Code 文件夹里已有美术资产，让它自己查找并放进游戏。AI 随后完成了素材与页面的对应和接入。

接着进入“预览—反馈—再修改”的迭代环节。作者打开游戏预览，检查角色、对话和整体效果。她认为 AI 写出的角色对话比较自然，有生活气息和情绪感；但最初的页面布局并不满意，于是直接用自然语言说明布局应该怎样调整。Claude Code 再次修改代码并交付新版本，改后的界面更符合她的预期。

最后，作者强调这套方法不局限于乙女游戏：职场逆袭、古风穿越、悬疑解谜等文字游戏都可以沿用同一流程。她也表示，想要提示词和相关文档的观众可以向她索取。

## 关键知识

- “不会写代码”指的是创作者不必亲自手写代码，并不代表游戏背后没有代码。代码、样式和项目文件仍由 AI 编程工具生成和修改。
- 一个有效的游戏提示词不能只有题材。至少要交代世界观、人物、剧情方向、核心玩法、数值系统、界面交互和开发要求，AI 才更容易产出结构完整、可继续迭代的原型。
- AI 代理的价值在于连续行动：它不仅回答问题，还能创建文件、写项目、寻找本地素材、运行预览，并根据反馈修改已有实现。
- 美术资产最好先整理进明确的项目文件夹，再告诉 AI 素材所在位置和使用要求，这比零散地逐张描述更高效。
- 第一个版本通常只是起点。真正实用的工作方式是先让 AI 做出可运行框架，再通过预览发现问题，用具体反馈逐轮调整布局、内容和交互。
- 视频展示的是快速原型流程，没有展开讲解上线发布、跨设备适配、测试、API 成本、密钥安全、素材授权或长期维护。因此“3 小时完成”更适合理解为做出一个可玩的初版，而不是完成可正式商业发行的产品。

## 可以照着做的行动清单

1. 安装并确认 Claude Code 或同类代理式开发工具能够在本机运行。
2. 申请模型 API，并按官方或可信文档完成配置；不要把真实 API Key 写进公开仓库、截图或可分享的提示词中。
3. 在动手前写一份游戏需求，至少包含题材与世界观、玩家身份、主要角色、剧情目标、玩法循环、状态数值、界面风格和技术要求。
4. 先要求 AI 生成最小可玩的框架，运行预览并确认主流程能走通，再继续增加内容。
5. 准备人物立绘、背景等素材，统一整理到项目目录，并明确告诉 AI 各类素材的用途。
6. 逐项试玩和检查：剧情是否连贯、对话是否符合人设、数值是否变化、图片是否对应、布局是否清楚。
7. 反馈时说具体，例如指出哪个页面、哪个区域、当前问题和期望效果，让 AI 修改后再次预览。
8. 如果准备对外发布，再补做测试、适配、版权检查、密钥管理、成本评估和部署工作。

一句话概括：这段视频提供的是一套“结构化需求 + AI 代理开发 + 本地素材接入 + 自然语言迭代”的文字游戏原型制作方法，门槛低、出初版快，但成品质量仍取决于需求是否具体、素材是否合适，以及后续检查和修改是否充分。
