# 这支视频实际展示了怎样用 Claude Code + Kimi 做乙女文游

这不是一条完整、无剪辑的软件开发录像，而是一条把成品预览、关键配置、提示词片段、代理执行界面和修改结果串起来的教程。视频提出的核心路径是：先让 Claude Code 通过 Kimi K2 Thinking 的 API 工作，再用自然语言生成游戏框架，补入用户自行准备的美术资产，最后继续用自然语言返修界面。

需要先划清证据边界：作者确实说“全程只用了三个小时，不写一行代码”，但视频没有连续计时、完整操作日志或他人复现，因此这是作者主张，不是被视频独立证明的事实。[00:06–00:09；CUE-003；TARGET-0006、TARGET-0007]

## 1. 先准备 Claude Code 和模型 API

视频把第一步标成“配置 API”。如果没有安装 Claude Code，屏幕给出的命令是：

```bash
npm install -g @anthropic-ai/claude-code
```

[00:17–00:21；TARGET-0029]

作者还给出一个替代方向：不想走这套配置时可以安装 Kimi CLI，并把它描述为能边思考边行动、具备 agent 能力且在国内使用方便的路径。视频展示了 Kimi CLI 页面和模型介绍，但没有完整交代 CLI 版本、安装命令，也没有证明它和后续 Claude Code 配置在功能上完全等价。[00:20–00:29；CUE-008 至 CUE-010；TARGET-0034、TARGET-0040]

随后画面进入 API Key 管理页：先是空列表，再点“新建 API Key”，最后出现创建确认弹窗。作者的操作说明是获取一个 API、复制好，再替换进配置文本。[00:29–00:33；TARGET-0049、TARGET-0052、TARGET-0054]

屏幕对 MacOS/Linux 展示了这些环境变量：

```bash
export ANTHROPIC_BASE_URL=https://api.moonshot.cn/anthropic
export ANTHROPIC_AUTH_TOKEN=${YOUR_MOONSHOT_API_KEY}
export ANTHROPIC_MODEL=kimi-k2-thinking-turbo
export ANTHROPIC_DEFAULT_OPUS_MODEL=kimi-k2-thinking-turbo
export ANTHROPIC_DEFAULT_SONNET_MODEL=kimi-k2-thinking-turbo
export ANTHROPIC_DEFAULT_HAIKU_MODEL=kimi-k2-thinking-turbo
export CLAUDE_CODE_SUBAGENT_MODEL=kimi-k2-thinking-turbo
```

[00:34–00:36；TARGET-0064、TARGET-0069]

这里的 `${YOUR_MOONSHOT_API_KEY}` 是屏幕上的占位符，不是真实密钥。视频没有建立账户权限、价格、额度、地区限制或安全存储方式，也不应从终端画面推断任何密钥值。

配置文本随后出现在终端，下一组镜头显示 Claude Code 的问候界面：“Hello! I'm Claude Code…”；作者据此宣布 K2 模型配置成功，可以开始发需求。[00:36–00:44；TARGET-0076、TARGET-0083；CUE-013、CUE-014]

## 2. 用一份结构化需求搭游戏框架

第二步被标成“搭框架”。作者明确说，需求大致要包含：

- 游戏世界观
- 主角
- 剧情
- 玩法
- 数值

画面确实展示了一份很长、类似代码结构的提示词文件，但字号和剪辑方式不足以在视频里完整恢复整份模板。因此，视频支持“这些字段被纳入需求”，不支持“整份模板已在画面中完整公开”。[00:44–00:53；CUE-015、CUE-016；TARGET-0092、TARGET-0101]

接着画面切到 Claude Code/终端和一份生成文档。可见内容包括项目结构、人物条目、数值字段以及较长的世界观与剧情文字。作者把生成结果概括为：主题是“大厂女工被裁后的都市生存困境”，已经有若干男性角色，核心数值也设计好了。[00:50–01:01；TARGET-0109、TARGET-0114、TARGET-0118；CUE-017、CUE-018]

这段可以确认的是“提示词画面之后出现了结构化框架输出”；不能确认的是完整提交动作、生成日志、所有文件是否一次生成，以及框架是否经过系统测试。

## 3. 美术资产不是代理凭空补出的，用户要先准备

文字框架完成后，作者主动指出一个缺口：游戏里已经有文字，但图片仍然不足，尤其缺少角色形象。随后视频进入“step3. 美术资产”。[01:00–01:05；CUE-019；TARGET-0124、TARGET-0126、TARGET-0130]

这里有一个很容易被摘要漏掉的依赖：作者让用户先自己“跑图”，再把人物和场景图片放进文件夹。画面显示了一个含多张人物、场景图片的文件夹；之后作者说，只需要告诉 Claude Code 文件夹里有美术资产，让它自己查找并放进游戏。[01:04–01:13；CUE-020、CUE-021；TARGET-0137、TARGET-0138、TARGET-0141]

视频没有展示跑图所用的模型、提示词、参数、角色一致性控制或版权处理。这些不能从“资产文件夹已经存在”倒推出。

后续预览显示办公室或城市背景、角色大图、对话框和对话框下方的小头像。这个结果支持“视频展示了资产进入游戏后的成品状态”，但文件命名、路径匹配、错误资产处理等中间细节被剪辑省略了。[01:12–01:21；TARGET-0143、TARGET-0145]

## 4. 对话质量是作者评价，不是客观测评

作者说预览中的对话都由 Claude Code 和 K2 编写，自己逐句看过；她评价人物交流自然、有生活气息和情绪，还认为比大部分编剧写得好。视频同时展示了几名不同角色和对话框，给出了她评价的对象。[01:17–01:29；CUE-023 至 CUE-025；TARGET-0148、TARGET-0150、TARGET-0154]

但这些镜头只是作者选择的样例。视频没有提供完整剧本、盲测、编剧对照或独立评审，所以“自然”“优于多数编剧”应保留为作者的主观判断。

## 5. 自然语言返修布局：前、操作中、后都看得到

旧版本把人物大图叠在场景背景上，对话框下方还保留一个小头像。作者说不喜欢这种布局。[01:29–01:31；TARGET-0157]

她在 Claude Code 输入的修改意图可以从屏幕读出：不喜欢人物和场景重合，对话时只保留对话框下的缩略图，并去掉背景里的角色。[01:31–01:34；TARGET-0162、TARGET-0165]

随后 Claude Code：

1. 读取 `index.html`；
2. 读取 `styles.css`；
3. 修改 CSS，把 `character-layer` 设为 `display: none`；
4. 报告已隐藏背景人物大图、保留对话框下方缩略图。

[01:33–01:37；TARGET-0165、TARGET-0167、TARGET-0168、TARGET-0170]

新预览与请求吻合：背景场景还在，人物大图不再覆盖场景，对话框下方的小头像仍被保留。作者评价“效果好多啦”。[01:36–01:39；TARGET-0171、TARGET-0172；CUE-028]

这一段是视频中证据链最完整的操作：旧状态、自然语言输入、读取与修改代码、完成摘要、新状态都出现了。不过，它仍没有展示自动测试或其他页面的回归检查。

## 6. 视频最后把单个案例推广成通用方法

结尾快速展示职场女性、古风女性和侦探造型女性三类画面，对应“职场逆袭、古风穿越、悬疑解谜”。随后作者说，即使不懂游戏开发、不懂代码、不懂 AI，只会说大白话，也能拥有自己的独立文游。[01:37–01:50；TARGET-0178、TARGET-0179、TARGET-0181、TARGET-0184、TARGET-0187；CUE-029 至 CUE-031]

这些画面证明视频展示了三种题材例子；它们不证明三套游戏都由本次相同流程、相同提示词完整生成，也不证明所有新手都能复现。视频最终让需要文档的观众向作者索取，但输入证据中没有这份文档。[01:49–01:51；CUE-032]

## 最终可执行结论与明确未知

从视频本身可以重建的最小流程是：

1. 安装 Claude Code，或考虑作者提出的 Kimi CLI 替代路径；
2. 在开发者平台创建 API Key；
3. 用屏幕所示 Moonshot 端点和 `kimi-k2-thinking-turbo` 环境变量配置 Claude Code；
4. 用包含世界观、主角、剧情、玩法、数值的提示词生成框架；
5. 用户自行准备美术资产并放入文件夹；
6. 告诉 Claude Code 查找并接入资产，打开预览；
7. 用自然语言描述布局问题，让 Claude Code 继续修改代码并检查新预览。

视频没有建立：真实密钥、完整模板、跑图方法、版本与计费、部署与分享、报错恢复、自动测试、连续三小时证据、完全零手写代码证据、他人复现成功率，以及对话质量和跨题材普适性的独立验证。
