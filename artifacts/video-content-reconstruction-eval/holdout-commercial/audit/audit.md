## 商业叙事：论点—证据—条件—反例—行动

### 论点

对于不值得专门跑医院、又不想被网上答案吓到的日常健康困惑，阿福应被选择为会追问、会回应、能给计划并陪伴记录的健康搭子。[EV-NAR-004][EV-NAR-005][EV-NAR-006][EV-NAR-007]

### 证据

- 主播自述使用体验：能支持“发布者这样评价产品”，不能独立证明产品表现。[EV-NAR-005][EV-NAR-006]
- 疲劳与咖啡 UI：支持示例中有多轮追问、问询进度、就医提示和 AI 参考免责声明。[EV-VIS-008][EV-VIS-009]
- 身材与睡眠 UI：支持示例中可输入资料、生成计划、建议任务并设置提醒/打卡。[EV-VIS-010][EV-VIS-012]
- 产品免责声明：支持示例至少声明不替代就医；不能证明医学准确率或专业等级。[EV-VIS-008][EV-UNK-002]

### 条件

- 适用叙事限定于日常、非急症问题；持续不适或警示症状应就医。[EV-VIS-008][EV-DISC-001]
- 用户需提交身份、健康史、身体数据、活动和习惯，建议依赖输入完整性与真实性。[EV-VIS-007][EV-VIS-010]
- 输出被界面定位为参考而非诊断或标准答案。[EV-NAR-006][EV-VIS-008]
- 将打卡理解为陪伴，需要用户接受每日提醒。[EV-VIS-012]

### 反例与失效情形

- 呼吸困难、胸痛、严重头晕、长期发热等警示症状下，AI 搭子不是适当终点；产品 UI 自己承认这一点。[EV-VIS-008]
- 单次示例能追问，不等于所有问题都相关、安全、不制造恐慌。[EV-UNK-001]
- 界面可能是预录、剪辑、预设或特定版本，视频不能证明普遍可复现性。[EV-UNK-001]
- 隐私没有任何实质证据，却要求输入多类敏感资料。[EV-VIS-007][EV-VIS-010][EV-UNK-002]
- “不会催”不能理解为无提醒，因为页面明确说每天提醒打卡。[EV-NAR-006][EV-VIS-012]

### 行动

最终行动号召是回答“你最想问的一个健康问题是什么”，目的更接近评论互动、需求表达和尝试产品的心理预备；没有二维码、下载路径、价格、优惠或限时条件，因此属于软转化而非硬销售。[EV-NAR-007][EV-VIS-015][EV-ABS-001]

## 未知与不可推出

- 新闻来源、日期、完整病因与事实准确性未知。[EV-VIS-001][EV-ABS-001]
- UI 是真实在线操作、预录演示、剪辑拼接还是预设脚本，以及在哪个版本可复现，未知。[EV-UNK-001]
- 32 岁、168cm、55kg 等是否为主播真实信息，未知。[EV-VIS-010]
- “高专业标准”的制定者、医学依据、专家审核和准确率未知。[EV-UNK-002]
- 隐私的数据收集范围、用途、共享、保留、训练使用、删除权、加密与审计未知。[EV-UNK-002]
- 产品平台、访问方法、费用、地区限制与账户要求未知。[EV-ABS-001]
- 主播是否获报酬、是否为广告投放、体验是否独立，未知。[EV-DISC-001][EV-ABS-001]
- 背景音频的曲名、曲风、作者与授权未知。[EV-AUD-002]
- 用户是否真的完成任务，睡眠、疲劳、注意力或体重是否改善，未知；视频没有前后测或结果数据。[EV-ABS-001]

## 结论

商业说服路径为：**恐惧显著化 → 自我投射 → 搜索失信 → 中间服务缺口 → 第一方 UI 功能演示 → 健康搭子人格化 → 专业/隐私信任收束 → 软 CTA**。[EV-NAR-001][EV-NAR-007]

证据最强的是“示例 UI 中确实有多轮追问、资料录入、计划、目标、提醒与参考/就医边界”；证据最弱的是“高专业标准、绝不制造恐慌、完全确保隐私、使用后会慢慢变好”。后者应始终保留为广告主张或未知，不能写成客观事实。[EV-VIS-008][EV-VIS-010][EV-VIS-012][EV-UNK-002]
