# dev-tool-map baseline 独立评估

## 结论

这份普通总结可读性很强，六个工具名和六类任务都没有漏，Vidu 段也正确写成“类似乔布斯的人物”，并意识到“任何人”属于宣传性表述。不过，硬 GATE 不能通过：它没有稳定地区分“视频把卡片、口播和结果剪在一起”与“结果确由对应工具生成”，又遗漏了卡片副文案、精确数量和即梦的静态—动态缺口。JUDGE 的可读性分不能覆盖这些 GATE 失败。

本评估只使用 `audit/audit.json`、`audit/audit.md`、`evidence/evidence-pack.json` 作为 ground truth，只把 `baseline/baseline.md` 与 `baseline/baseline-process.md` 当作候选。没有读取 skill-run 或人工报告。

### 计数口径

- Evidence coverage 以审计的 `AE-001` 至 `AE-025` 作为内容知识单元。`AE-026` 是证据包悬空帧问题，不要求普通总结覆盖。
- 普通总结没有帧号、镜头号或段落时间码。Timestamp accuracy 只检查候选实际存在的“约 16 秒 / 16.56 秒”这一条时间陈述；这不是给候选补证据。
- Unsupported inference 按可独立核验的事实、能力和程序命题分句计数。纯安全建议不计；若建议直接断言片中没展示的输入—输出流程，则计为错误。
- Unchecked channels 只列出能由过程说明确认未检查的 `audio_beyond_transcribed_speech`。没有因为普通总结未逐项列通道，就假造它执行过通道审计。

## Critical questions

正确覆盖 7 项：

- CQ-01：六项工具—任务映射与速览结构。
- CQ-02：六个工具名全部辨认，包括 Runway。
- CQ-04：Vidu 同框者写为“类似乔布斯”，没有写成真人合拍。
- CQ-05：“任何人”被正确限定为宣传式表述。
- CQ-07：候选指出真实操作、耗时与稳定性未展示，能够支持“一键不可核验”的 unknown。
- CQ-08：候选至少辨认出 PPT 为多套/多种版式，而非一套。
- CQ-15：明确判断不是教程，且缺入口、提示词、参数、费用、耗时与稳定性。

未覆盖 8 项：

- CQ-03：没有明确回答“编辑配对不等于生成因果”，反而多处继续使用能力事实语气。
- CQ-06：没有明确 Runway 是至少两套不同于原白衣的输出造型。
- CQ-09：没有把 PPT 的可编辑性、内容正确性和 Manus 生成归因保持为 unknown。
- CQ-10、CQ-11：没有保留“图片创作工具”卡片与“做动漫”之间的不一致，也没有说明动画可能依赖其他生成或剪辑环节。
- CQ-12：没有区分卡片产品归属、“免费”“全球首款”等片内文案与外部核验事实。
- CQ-13：没有处理“AI生成”标签不能证明具体工具归因。
- CQ-14：没有明确六项之间不存在程序调用、文件传递或工作流链。

## 关键 GATE 诊断

### 身份

Vidu 的人物身份处理是对的：候选用“类似乔布斯”，没有宣称与 Steve Jobs 真人合拍。

通义和即梦两段则越过了证据边界。“真人被替换”把可见的造型变化升级成了身份替换；“真人画面被转成动漫插画”又把相似元素和相邻剪辑升级成输入身份连续与转换过程。审计只允许说前后造型变化、相似角色元素和动画化结果可见。

### 卡片

六个工具名完整，这是 baseline 最重要的成功点，也说明它没有落入 Runway 卡片被稠密采样跳过的高风险遗漏。

但六张卡片的来源/类别副文案全部没有保留，尤其漏掉了即梦卡片写的是“抖音旗下免费 AI 图片创作工具”。同时，候选没有说明六次口播都用“这个”，工具卡是确定代词所指的关键载体。结果是工具名有了，卡片的结构性作用没有被重建。

### PPT 数量

候选的“成套演示文稿页面和多种版式缩略图”只回答了“不是单页/单一版式”，没有保留审计中的精确信息：连续展示三套不同视觉风格的缩略图网格，每套画面可见 12 页。这个遗漏同时损害 evidence coverage 与 compression without loss。

### 即梦归因

候选把结尾写成静态“动漫插画”，漏掉人物、头显、鹿和蝴蝶随帧变化所形成的动画化呈现；又将其直接概括为即梦的图像风格化和动漫创作能力。审计给出的正确边界是：视频把即梦与“做动漫”配对，结果确有运动，但卡片只称图片工具，没有任何界面或过程说明即梦是否单独完成了动画，也无法确定“动漫”的具体产物类型。

### 无 UI 与生成因果

候选正确指出视频不是教程，也没有入口、提示词、参数、费用、耗时和稳定性。这一负事实本应导向更强的结论：视频只证明卡片、口播和演示的编辑配对，不能证明工具生成因果。

实际文本却多次写成“说明它可用于”“生成了”“被转成”“即梦被用于”，还从六项宣传演示直接派生工具选择建议。这里的 GATE 是实质性 FAIL，而不是措辞偏好：缺少界面、输入、处理记录和导出文件时，编辑相邻不能自证能力归因。

## Process dependencies 与 unknowns

候选覆盖了两条编辑关系：工具名/口播逐段配对，以及口播功能/视觉结果逐段配对。它没有保留同一主持人和房间作为跨条目连续锚点，也没有明确六项之间无程序依赖或文件传递，因此是 2/4。

九个审计 unknown 中，只对输入/提示/参数缺失和版本/费用/耗时/稳定性这一组保持了足够克制。结果具体归因、Runway“一键”、Vidu 肖像来源、Manus 文件属性、即梦动画流程、附加音频语义和卡片宣传真实性均未被完整标为 unknown；部分还被反向写成正面能力或流程。

## Meta-audit

本轮评估显式覆盖了审计列出的信息载体、七个 meaning changes、并列关系和编辑依赖。唯一无法由候选过程证明已检查的附加音频层已放入 `uncheckedChannels`，没有把它伪装成 PASS。因此 meta-gate 本身通过；这不改变候选的多项硬 GATE 失败。
