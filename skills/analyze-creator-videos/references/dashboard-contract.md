# Creator Dashboard contract

The Dashboard is a decision surface. Preserve the existing Dashboard when updating a creator; extend it instead of creating a parallel replacement.

## Information order

1. Analysis purpose, method, and supported decisions.
2. Creator positioning and audience promise.
3. Full public-corpus baseline and metric boundaries.
4. Topic and format portfolios.
5. High/median/average/low patterns and success/failure mechanisms.
6. All-post browser with List and Gallery views.
7. Evidence-grade selected-video detail.
8. Publishing and visual-language patterns.
9. Launch plan and experiments.
10. Method, coverage, and unknowns.

## Portfolio statistics

For every topic and format cluster show post count, high-threshold count/share, median likes, mean likes, and maximum likes. State whether labels are semantic annotations, title heuristics, or both; labels may overlap.

## List and Gallery

List preserves dense comparison. Include tier, title, labels, published time, duration, likes, other available metrics, mechanism summary, and evidence status.

Gallery uses real covers or evidence frames. Every card includes title, tier, content form, core message, mechanism hypothesis, public metrics, and a route to deep evidence when available.

## Selected video

Expose selection reason, viewer cognitive change, content architecture, core units, sparse/dense frame toggle, complete transcript with timecodes and frame/shot mapping, provenance-separated findings, unknowns, full report link, and gate status.

## UX rules

- Keep one primary Dashboard URL per creator.
- Establish a clear reading sequence instead of an equally weighted card wall.
- Use tabular numerals and concise labels for data.
- Keep evidence boundaries visible near conclusions and exports.
- Preserve mobile order and prevent horizontal overflow.
- Validate all controls in a real browser.
