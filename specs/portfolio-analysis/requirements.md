# 系列与博主分析 — 需求

## 目标

把单帖报告扩展为三个分析入口：单帖、自定义系列、博主主页。博主入口可由单帖中已识别的作者直接发起。

## 用户故事

- 作为运营者，我希望从一条笔记进入对应博主分析，以判断这次爆发是偶然还是稳定能力。
- 作为运营者，我希望提交多条帖子组成系列，以比较同一选题/形式的效果变化。
- 作为运营者，我希望看到博主的内容支柱、爆款依赖和稳定模式，而不是一串独立帖子报告。

## 验收标准

1. 当单帖已取得作者 ID 和访问令牌时，系统应提供“分析该博主”操作。
2. 当用户发起博主分析时，系统应采集主页资料及最多 12 条近期/代表笔记，并保留每条原始公开指标。
3. 当可用帖子不少于 5 条时，系统应计算互动中位数、爆款依赖度、稳定度、内容支柱和异常帖子。
4. 当帖子不足 5 条时，系统应显示样本不足，不外推稳定模式。
5. 当用户提交 2–20 条链接时，系统应创建系列分析，并比较归一化互动结构与选题/包装共性。
6. 当小红书登录、扩展或主页采集不可用时，系统应保留任务并显示明确阻塞原因，不得使用演示数据替换。
7. 系列/博主报告应区分公开事实、跨帖观察和机制假设。
8. 博主报告应明确区分“规模”“稳定性”“爆款依赖”“内容深度”和“商业转化未知”。

## 非目标

- 不自动关注、点赞、评论或发布。
- 不在没有后台数据时判断真实成交、投流增量或粉丝画像。
- 不把标题关键词聚类直接称为完整内容战略。
