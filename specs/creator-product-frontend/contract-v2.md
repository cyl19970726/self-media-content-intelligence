## 0. 项目根心智模型（一切页面结构的依据）

**归纳决策循环**（来自 Owner 的实践演化）：

```
① 分档  内容分成三类：被用户认可 / 一般喜欢 / 不认可（实现为高/中/均值附近/低四档）
② 打标  把账号内容分类、打标签（内容地图：引擎 / 支柱 / 样本类型）
③ 读律  从每一类里读出规律：这类为什么被认可、那类为什么不认可
④ 迁移  复制被认可的规律、避开被否定的问题 → 自己的内容决策（起号方案/内容规划）
```

产品 = 让这个循环**跑得更快、更可靠**的引擎。任何页面结构问题都回到这个循环来回答。

**产品服务的消费者**：
1. **运营者（Owner）**：不知道该发什么时，来拿"该复制什么、该避开什么"。
2. **AI 伙伴（agent）**：需要结构化的"这个 IP 什么好 / 什么不好 / 为什么好 / 复制什么"，
   来辅助写内容、做规划。深度分析（拉片、内容理解 skill）是它的价值引擎，不是附件。

## 1. 博主对比的心智模型（跨账号的可信度判据）

同一个循环从"一个账号内部"扩展到"多个账号之间"。对比的产出是**规律的可信度**：

| 规律出现在哪 | 性质 | 决策 |
|---|---|---|
| 同一标签在多个账号都成立 | 赛道规律（平台/品类成立，不依赖 IP） | 高置信，直接复制 |
| 只在一个账号成立、别处失效 | IP 能力（依赖个人特质） | 不复制，承认边界 |
| 多账号都缺的标签 | 定位空缺 | 差异化机会 = 自己的生态位 |
| A 的规律 × B 的规律 | 可组装 | 跨账号拼出内容组合 |

对比单位不是"博主"，是**标签/机制**（槽位化数据天然可对比）。
对比台是一级页面，不挂在任何博主页里。

## 2. 页面架构（v2）

| # | 页面 | 路由 | 循环位置 |
|---|---|---|---|
| 1 | 工作台首页 | `/` | 入口（单帖/系列/博主三种分析） |
| 2 | 单帖分析页 | `/runs/:id` | ① 单条分档 |
| 3 | 博主总览 | `/creators` | 选研究对象（当前 2 个 IP） |
| 4 | 博主页（研究台） | `/creators/:id` | ①②③④ 完整循环 |
| 5 | **跨 IP 对比台** | `/benchmark` | ③ 升维：规律可信度 |
| 6 | 视频级证据页 | `/creators/:id/videos/:videoId` | ③ 的证据（拉片/内容还原） |

### 博主页叙事重排（按循环，不按数据源）

```
01 这个 IP 值不值得学   定位 + 基本盘 + 分档总览（3 秒层）
02 什么好、什么不好     表现分层：被认可/一般/不认可 → 每类机制诊断（核心问题）
03 为什么好             证据级还原入口 → 视频级证据页（深度分析 = 核心工作区）
04 内容地图             槽位化标签：引擎/支柱/样本类型 + 形式统计（② 打标）
05 内容库               List/Gallery 全部内容（① 的原料）
06 发布节奏与画面        辅助变量；缺数据具名缺省
07 赛道位置             该 IP 在同赛道对比中的位置 → 跳 /benchmark
08 我的内容决策         起号方案：复制什么/避开什么/首批内容规划（④ 迁移收口）
09 方法边界             知道/推断/不知道 + 口径 + 采集时间
```

### 跨 IP 对比台 `/benchmark`（新一级页面）

```
头部   当前对比集（2 个 IP）+ 对比口径说明
槽位 1 机制对比：保存型/传播型/证明型等标签在多个账号的各自表现（真实计算）
槽位 2 可信度分层：赛道规律 / IP 能力 / 定位空缺 三栏
槽位 3 空缺地图：无人占的标签 → 差异化机会
收口   组合策略：跨账号规律组装成"我的首批内容组合"
```
