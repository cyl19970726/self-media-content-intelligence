# Creator Product Frontend · Phase 0 产品合同 v1 — DEAD

> **状态：已被 contract-v2.md 取代（2026-08-17）。仅存档，不作为任何实现依据。**
> 依据：harness-frontend-product-design（Phase 0 文字合同，判断权归属 Owner）。

## 0. 目标与非目标

**目标**：把 Signal Room 从"一组报告"升级为"AI 赛道博主研究后台"——一个产品：
全部页面共享一套信息架构、导航与视觉语言；每个博主的页面是同一组组件的不同数据实例；
结论永远可下钻到证据；页面收口永远是行动。

**非目标**：
- 不做小红书站内运营/发布/互动功能（采集只读）。
- 不做多租户/账号系统。本地单人使用。
- 不把现有报告内容重写——数据与证据复用现有 artifacts，只重建呈现层。
- 本轮不迁移 CLI（`npm run selfmedia`）形态，只做 web 前端。

## 2. 形态合同：产品语言（与报告的边界）

1. **导航常驻**：博主页有左侧 rail（01-09 节锚点）+ 面包屑（总览 → 博主 → 视频）。页面内不允许出现"从头滚到尾"的阅读路径。
2. **状态常驻**：每个数据块带状态徽标——`已覆盖`（有证据）/ `未采集`（具名缺省）/ `过期`（采集时间 > 阈值）。状态是产品的一等公民，不是注释。
3. **元信息常驻**：数据口径（公开数据 vs 账号后台）、采集时间、样本量——固定在数据区头部，不埋进正文。
4. **下钻不滚动**：博主页 → 视频级证据页是路由跳转，不是页面内展开。
5. **行动收口**：每页有明确的下一步（博主页 → 起号方案；视频页 → 该视频的可复制要素）。
6. **空态有原因**：缺数据区块显示"为什么缺 + 怎么补"，不空白不隐藏。

## 3. 各页布局合同

### 3.1 工作台首页 `/`

- 首视口：品牌 + 链接输入 + 平台说明 + 最近档案 rail。
- 右上：运行中任务状态（实时刷新）。
- 底部：入口矩阵——三个分析模式（单帖 / 系列 / 博主）+ 博主研究入口。

### 3.2 单帖分析页 `/runs/:id`（改造）

- 保持现有 ReportV2 六层证据结构，但：加状态栏（阶段徽标 + 数据口径）、
  作者信息区加"分析该博主"动作（已有）、结论区尾部加"把结论加入起号实验"动作。

### 3.3 博主总览 `/creators`

- 头部：定位语 + 已覆盖博主数 + 分析模式说明。
- 主体：博主卡片网格（已确认 v0 形态，本轮重设计视觉）。
- 每卡：定位一句话 / 盘面数字 / 槽位标签 / 覆盖度 / 两个入口（研究台 + 证据库）。

### 3.4 博主页 `/creators/:id`（核心）

九节结构（rail 锚点导航），自上而下：

```
01 定位与契约   谁、多大盘面、值不值得学（3 秒层）
02 基本盘       中位数/均值/最高 + 点赞分布 + 平均值档诊断（3 秒层收尾）
03 内容地图     槽位化：引擎(红发魔女) / 支柱(张咋啦) / 样本类型(人类最强编导) + 形式统计
04 表现分层     高/中/均值附近/低 四档 + 跨档结论 + 每条可下钻（30 秒层）
05 内容库       全部内容 List/Gallery 双视图 + 档位/主题筛选
06 证据级还原   选视频 → 跳视频级证据页（深钻层入口，不在本页展开）
07 发布节奏/画面 星期/时段 + 画面语法；缺数据 → 具名缺省"未采集"
08 起号方案     收口：我们明天怎么开始（深色区）
09 方法边界     知道什么/推断什么/不知道什么 + 数据口径 + 采集时间
```

- 首视口（不滚动可见）：品牌面包屑 + 定位一句话 + 粉丝/赞藏/样本数 + 01/02 摘要。
- 槽位化规则：03 的"内容地图"是同一槽位，三个博主各表其内容，不互相翻译。
- 对标模块（可选）：挂 04 之后，双列并排两博主同槽数据。

### 3.5 视频级证据页 `/creators/:id/videos/:videoId`（统一模板）

- 头部：标题 + 一句话主旨 + 表现数据（赞/藏/评/分享 + 相对档位分位）。
- 主体五段（video-library 模板已被验证，沿用并统一）：
  a. 内容架构（它怎样让观众继续看）
  b. 完整文章（把视频读成一篇文章）
  c. 稀疏帧（8 张看懂故事线）/ 密集帧（不漏视觉转折）
  d. 逐字稿与逐句画面（cue ↔ 帧对齐）
  e. 知识单元与未知边界（证据引用 + 时间码）
- 底部：该视频的可复制要素 + 回到博主页。
- 数据源三分归一：video-library 报告 / content-reconstruction-v1 evidence / zhang deepDives / human-director breakdowns → 统一 JSON 契约。

### 3.6 对标视图（可选槽）

- 双列布局，同一槽位两博主并排（如引擎 vs 支柱在"内容地图"槽并排）。
- 只在两个博主都有该槽数据时渲染。

## 4. 视觉语言（信条级，Phase 2 测量时不得违反）

1. **平面 + 发丝线**：无阴影、无渐变堆砌；分隔用 1px 线。
2. **纸张底色 + 墨色**：延续 SIGNAL ROOM 报纸档案美学（--paper/--ink 已有 token）。
3. **强调色单一职责**：teal = 证据/已覆盖；orange = 行动/待办；red = 边界/风险。不装饰。
4. **mono 字体做元信息**（编号/口径/状态），衬线/无衬线做正文与标题。
5. **密度由层决定**：L1 大数字大标题；L2 表格/卡片网格；L3 帧+文字稿并排。
6. **产品元素与报告元素分开**：导航、状态、筛选、按钮 = 产品 chrome，永远与证据内容分区。

## 6. UX 行为规则（通用条款）

- 写操作等权威回执（分析任务的创建/重试有服务器确认，不乐观假成功）。
- 数据过期/刷新失败时：只读视图保留 last-good，写操作禁用并说明。
- 键盘可达：所有导航/筛选/下钻 Tab 可达；Esc 关闭弹层。
- 空态给"为什么空 + 能做什么"。
- 图片/帧一律懒加载，URL 一律由数据层提供——**页面不自己造路径**
  （gate，来自 2026-08-17 图片丢失事故：数据文件写死站点根前缀 `/artifacts/...`，
  服务切换后全 404。修法：页面相对路径 + no-cache）。

## 8. 文案语调

quiet operations：陈述事实、无感叹、无营销词。数字必须带口径（"公开数据"）；不确定就写不确定。
