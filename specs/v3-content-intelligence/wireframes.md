# Signal Room V3 — 三张关键页面线框说明

可交互预览见同目录下的 `wireframes.html`。预览中的数字和内容只用于验证信息层级，所有演示值均标记为非真实分析结果。

## 1. 单帖研究台

### 页面要回答的问题

“这条内容为什么表现成这样，证据在哪里，下一条应该测试什么？”

### 首屏结构

```text
┌────┬──────────────────────────────────────────────┬────────────────┐
│工作│ 万能投递 / 项目切换                           │                │
│区  ├──────────────────────────────────────────────┤                │
│导航│ 研究问题 + 目标 + 样本与数据边界              │ 证据检查器     │
│    ├──────────────────────────────────────────────┤ 原文 / 指标     │
│    │ 一句话判断 │ 相对作者 │ 相对题材 │ 下一步动作  │ 评论 / 时间码   │
│    ├───────────────────────┬──────────────────────┤ 公式 / 反证     │
│    │ 视频、帧与拉片时间轴   │ 内容 X-Ray           │                │
│    │                       │ 人群→需求→承诺→证据   │                │
│    ├───────────────────────┴──────────────────────┤                │
│    │ 机制假设 / 反证 / 替代解释 / 实验             │                │
└────┴──────────────────────────────────────────────┴────────────────┘
```

### 关键交互

- 点击脚本段、镜头、判断或指标，右侧证据检查器定位到对应原文、评论、帧或公式。
- 从任何 Finding 可以执行“确认”“修正”“保存为内容模型”“生成 Brief”。
- “分析该博主”不在当前页面向下追加内容，而是创建／打开独立博主项目。
- “加入专题”把该帖子复用为 ProjectSample，不重新采集一份内容。

## 2. 多帖／专题对照台

### 页面要回答的问题

“在可比样本中，什么真正区分表现好与不符合预期的内容？”

### 首屏结构

```text
┌────┬──────────────────────────────────────────────┬────────────────┐
│工作│ 专题问题 / 目标 / 观察窗口 / 可比性状态       │                │
│区  ├──────────────────────────────────────────────┤                │
│导航│ 样本分布：赢家 / 中位 / 低表现 / 排除         │ 证据检查器     │
│    ├──────────────────────────────────────────────┤ 代表帖子       │
│    │ 对照矩阵                                     │ 反例           │
│    │ 维度 × 赢家 × 中位 × 低表现 × 区分力          │ 计算口径       │
│    ├──────────────────────────────────────────────┤ 混杂因素       │
│    │ 区分因素 │ 常见但无区分力 │ 混杂因素          │                │
│    ├──────────────────────────────────────────────┤                │
│    │ 内容空位 / 下一批选题 / 实验                  │                │
└────┴──────────────────────────────────────────────┴────────────────┘
```

### 关键交互

- 用户可修改赢家和低表现分组定义，系统立即说明哪些结论失效或需要重算。
- 点击任一维度后，样本按“支持／反例／未知”筛选，不只展示漂亮的赢家案例。
- 可比性警告一直可见；样本不足时页面降级为探索模式。
- “生成下一批选题”必须引用专题结论、适用范围和反例。

## 3. 博主研究台

### 页面要回答的问题

“这个账号怎样持续服务一群人，哪些能力稳定、哪些偶然、哪些可以用于起号？”

### 首屏结构

```text
┌────┬──────────────────────────────────────────────┬────────────────┐
│工作│ 博主身份 / 采集状态 / 样本边界 / 关注         │                │
│区  ├──────────────────────────────────────────────┤                │
│导航│ 账号操作系统：受众→任务→承诺→支柱→形式→结果   │ 证据检查器     │
│    ├──────────────────────────────────────────────┤ 代表帖子       │
│    │ 内容支柱矩阵：占比 / 表现 / 稳定性 / 代表样本  │ 高表现 / 低表现│
│    ├───────────────────────┬──────────────────────┤ 主页 / 评论     │
│    │ 视觉语法样本墙         │ 脚本母版             │ 限制与未知     │
│    ├───────────────────────┴──────────────────────┤                │
│    │ 可复制能力 │ 身份/资源依赖 │ 差异化起号方向      │                │
└────┴──────────────────────────────────────────────┴────────────────┘
```

### 关键交互

- 点击内容支柱，展开该支柱的代表帖、高表现帖、低表现帖和发布时间分布。
- 点击视觉语法或脚本母版，进入样本墙并查看真实画面帧／脚本段，而不是只看关键词。
- 起号建议必须从已确认 Finding 生成，并同时展示“可复制”“账号依赖”“资源依赖”。
- 用户可把博主加入关注列表；后续新增内容形成新快照，不覆盖旧研究结论。

## 4. 三页共用规则

- 页面顶端始终显示研究问题、运营目标、样本边界和数据新鲜度。
- 技术采集阶段放在次级诊断抽屉，不抢占研究首屏。
- Finding 颜色固定：事实绿、观察墨色、假设橙、未知灰、风险／反证红。
- 右侧检查器是证据面板，不是通用属性栏；任何数字或判断都能追溯。
- 小于 1024px 时证据检查器变为底部或右侧抽屉；小于 768px 时矩阵切换为可排序列表。
