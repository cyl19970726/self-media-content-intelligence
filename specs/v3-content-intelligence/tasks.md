# Signal Room V3 — 实施任务计划

> 状态：等待产品确认。用户确认 PRD、数据模型和线框图后才进入执行。

## Phase 0 — 决策确认

- [ ] 0.1 确认三种研究模式与四个主工作区
  - 确认单帖、多帖专题、博主为三类独立项目。
  - 确认研究台、样本库、内容模型、发布复盘为主导航。
  - 确认 Notion 是选择性同步层，而不是运行时数据源。
  - _Requirements: R1, R2, R11_

- [ ] 0.2 确认三张关键页面线框
  - 审核首屏问题、对照方式、证据检查器和行动入口。
  - 记录需要保留、删减或调整的信息层级。
  - _Requirements: R3, R4, R5, R9_

## Phase 1 — 领域模型与兼容层

- [ ] 1.1 建立 V3 Zod 领域契约
  - 新增 Creator、ContentItem、MetricSnapshot、EvidenceItem、ResearchProject、ProjectSample、AnalysisRun 和 Finding 契约。
  - 为平台缺失字段保留 `null`，为判断保留 `unknown`。
  - _Requirements: R2, R6, R10_

- [ ] 1.2 建立 SQLite 规范化表与迁移版本
  - 创建内容资料、研究项目、结论和关联表。
  - 保留现有 `runs` 与 JSON 报告，迁移过程幂等。
  - 增加唯一键、外键和必要索引。
  - _Requirements: R2, R8_

- [ ] 1.3 实现 V2 Run 到 V3 Project 的迁移适配器
  - 旧报告首次打开时生成单帖项目。
  - 映射作者、内容、指标、评论、镜头和旧结论。
  - 无法映射的证据标记为需要复核，不补造字段。
  - _Requirements: R2, R6, R10_

## Phase 2 — 万能投递与项目外壳

- [ ] 2.1 实现输入预览与对象类型识别
  - 支持帖子、分享文案、多链接、主页和关键词研究问题。
  - 主页短链创建博主项目；多链接创建专题项目。
  - 输入失败时保留原文并给出明确边界。
  - _Requirements: R1, R10_

- [ ] 2.2 实现项目 API 与项目状态
  - 创建、读取、更新项目和研究问题。
  - 添加、排除和复用样本。
  - 把技术 Run 状态移入次级诊断信息。
  - _Requirements: R1, R2_

- [ ] 2.3 实现 V3 共享工作区外壳
  - 建立四个主工作区导航、万能投递栏和项目切换。
  - 实现桌面三栏、窄屏折叠导航和证据抽屉。
  - 移除主流程中的永久 Run Archive。
  - _Requirements: R9_

## Phase 3 — 单帖研究台

- [ ] 3.1 重组单帖首屏决策摘要
  - 显示研究问题、运营目标、样本边界、相对位置、未知和下一步动作。
  - 不再用综合分或技术阶段作为主结论。
  - _Requirements: R3, R6, R9_

- [ ] 3.2 实现真实内容 X-Ray 与拉片交互
  - 将人群、任务、承诺、脚本、画面、证据和 CTA 建立可点击关系。
  - 点击节点联动右侧原文、帧、转录和评论证据。
  - 媒体缺失时正确降级。
  - _Requirements: R3, R6_

- [ ] 3.3 实现单帖行动入口
  - 保存 Finding 为内容模型草稿。
  - 生成带来源、变量、风险和指标的 Brief／实验。
  - 将帖子加入专题或创建独立博主项目。
  - _Requirements: R2, R7_

## Phase 4 — 多帖／专题对照台

- [ ] 4.1 实现专题样本管理和可比性检查
  - 支持 2–100 条链接、样本库选择和候选样本。
  - 检查观察窗口、作者体量、内容形式、时效和投流未知。
  - 样本不足时降级为探索模式。
  - _Requirements: R4, R10_

- [ ] 4.2 实现目标驱动的分组引擎
  - 按运营目标建立可审计指标。
  - 生成赢家、中位、低表现和排除分组。
  - 保存分组规则、样本量和计算公式。
  - _Requirements: R4, R6_

- [ ] 4.3 实现差异矩阵、反例与混杂因素
  - 比较统一内容维度并显示覆盖率、效应方向和置信度。
  - 每个区分因素同时展示代表帖、反例和混杂因素。
  - 区分“可能有效”和“常见但无区分力”。
  - _Requirements: R4, R6, R9_

- [ ] 4.4 实现专题机会与选题组生成
  - 从已确认结论生成内容空位和下一批选题。
  - 每个选题引用来源结论、适用范围和验证指标。
  - _Requirements: R7_

## Phase 5 — 博主研究台

- [ ] 5.1 实现博主主页与跨时间样本采集
  - 继续使用现有小红书 CLI／扩展链路。
  - 保存主页快照和至少 12 条跨时间样本。
  - 登录阻塞时保留真实项目和原因，不替换演示数据。
  - _Requirements: R5, R10_

- [ ] 5.2 实现账号内容操作系统
  - 建模受众、用户任务、账号承诺、内容支柱、形式和用户响应。
  - 支柱同时展示占比、表现、稳定性和代表样本。
  - 样本不足时限制外推。
  - _Requirements: R5, R6_

- [ ] 5.3 实现视觉语法与脚本母版样本墙
  - 基于真实封面、代表帧、镜头和脚本段形成可浏览样本墙。
  - 每个母版列出高表现、低表现和常规样本。
  - _Requirements: R5, R9_

- [ ] 5.4 实现起号决策输出
  - 区分可复制能力、身份依赖、资源依赖和差异化方向。
  - 只从已确认 Finding 生成起号 Brief。
  - _Requirements: R5, R7_

## Phase 6 — 内容模型、发布与复盘闭环

- [ ] 6.1 实现 Finding 人工审阅与修订历史
  - 支持确认、修正、否定和替代。
  - 保留支持证据、反证和历史版本。
  - _Requirements: R6_

- [ ] 6.2 实现内容模型与 Brief 工作流
  - 建立成功结构、失败模式、脚本母版、视觉语法和平台打法。
  - 从 Finding 生成 Brief 并保持追溯。
  - _Requirements: R7_

- [ ] 6.3 实现发布内容关联与指标快照导入
  - 关联平台内容 ID、Brief、Experiment 和实际版本。
  - 公开与后台指标按观察时间追加保存。
  - _Requirements: R8, R10_

- [ ] 6.4 实现复盘对原假设与模型的更新
  - 复盘可确认、修正或否定原 Finding。
  - 验证结果更新 ContentPlaybook 状态，不静默覆盖旧结论。
  - _Requirements: R8_

## Phase 7 — Notion 与多平台适配

- [ ] 7.1 实现成熟结论的选择性 Notion 同步
  - 同步项目、博主雷达、内容模型、Brief 和复盘摘要。
  - 原始媒体只保留缩略图或本地链接。
  - 同步失败不影响本地状态。
  - _Requirements: R11_

- [ ] 7.2 建立平台能力矩阵
  - 为小红书、视频号、抖音、YouTube 和 X 定义可用指标、内容维度和缺失边界。
  - 禁止跨平台使用不存在的字段或错误换算。
  - _Requirements: R10_

## Phase 8 — 验证与发布门禁

- [ ] 8.1 单元与迁移测试
  - 验证去重、快照、空值、分组、证据关系和幂等迁移。
  - _Requirements: R2, R4, R6, R8, R10_

- [ ] 8.2 三条真实纵向流程验证
  - 单帖 → 内容模型 → Brief。
  - DeepSeek 专题 → 赢家／低表现对照 → 选题组。
  - 人类最强编导 → 真实采集 → 博主操作系统 → 起号 Brief。
  - _Requirements: R1–R10_

- [ ] 8.3 响应式与可访问性验证
  - 在 320、768、1024、1440px 验证三种页面。
  - 验证键盘导航、证据抽屉、文本对比度和无横向溢出。
  - _Requirements: R9_

- [ ] 8.4 构建与回归门禁
  - 运行类型检查、Lint、单元测试和生产构建。
  - 浏览器验证首页、旧报告迁移和三种项目页无新控制台错误。
  - _Requirements: R1–R11_
