# 分析方法

## 1. 先建立逐帖理解，再提出跨帖结论

阅读冻结批次中每篇已构建样本的全部 builderLenses：内容还原、编导逻辑、画面与剪辑，以及它的评估边界。不要只读摘要、标题或最高赞帖子。全体作品清单与选样分层用于理解分布，不代替深读。

在内部整理每篇的四个方面，不必另交一份重复报告：

- 内容：具体问题、概念、步骤、条件、数字、例子、限制；读者能否复述，而非只知道作者“介绍了某方法”？
- 表达：怎样开场、推进、证明，画面究竟解释了什么；区分展示与仅仅宣称。
- 数据：发布时间、在本次观察范围中的表现位置、所属比较组及口径。
- 比较价值：它支持什么判断、与哪篇互补或矛盾、对什么模式构成反例。

已有原文可回答但单帖遗漏的知识，标为单帖还原缺口并指出位置；不要由综合暗中重建，也不要误称世界未知。OCR 失败不等于画面文字不可读，必要时指出可回查的帧交给单帖修订。回查发现的遗漏只用于定位修订任务；单帖新版本登记前，不把它作为综合中新增加的深度事实。来源本身仍不能回答时，才保留该材料范围内未知。

## 2. 按问题建立联系，保留冲突

先问多篇共同解释了哪个实际问题，再组织关系：共同条件、互补机制、适用场景不同、随时间改变的立场、明确矛盾、仍未比较。不要把所有差异都合理化成“始终一致”，也不要把不同任务下的建议强行当矛盾。

知识联系必须具体到概念、条件和方法。例如“短测能跑与长期可用不同，需要考虑散热和维护”比“先抛问题再给方案”更接近知识地图；后者属于表达模式。研究中技术、生活场景、商业、信任与分发等维度可以从材料生长，不预设所有博主的价值相同。

逐条尝试找反例；找不到就说当前没有足够反证，不虚构反例填字段。单篇只能支持局部观察，重复出现也不能自动证明普遍规律。

## 3. 五个互补部分

按当前产品合同的五部分输出 crossPostResearch，每部分一次：

1. **value／价值**：这个博主持续提供什么价值？用具体内容证明，说明受众推断及适用边界。
2. **knowledge／知识与问题地图**：样本共同讲清了哪些概念、方法、条件与关系？读者能学到什么，哪篇能进一步解释？不以套路、设备名列表或“有五项能力”代替知识。
3. **patterns／内容模式**：选题、论证、编导、画面、剪辑中反复出现的做法，以及不符合的样本。把表达与具体内容及证据连起来。
4. **performance／表现与反例**：把高、基准、低表现的内容差异并置，讨论发布时间、话题、样本选择等混杂因素。只能描述相关性，不宣称某技巧导致爆款。
5. **next_questions／后续问题**：源于已获得认知的具体问题。区分材料无法回答、单帖遗漏、跨帖尚未比较；兼顾知识与表达，不全变成产品真假调查，也不输出我们的创作计划。

每条 finding 是有证据的跨帖判断：statement、事实类别、置信度、逐帖 support、可得的 counterexamples、boundary、openQuestions。证据观察写清该帖实际提供了什么，不只贴链接。support 必须支持该条判断，counterexamples 必须实际限制或反驳它；仅仅不同的主题不算反例。反例若推翻原判断，就收窄或改写 statement，并同步 boundary，不能保留绝对结论再把相反证据藏进附注。保持自然中文，ID、Schema 枚举和引用保持原值。

## 4. 自适配分类

完整构建时，分类由同一次综合 Builder 负责，并非另有独立分类 Agent：从实际材料发现紧凑的标签表，再对冻结清单中的每篇标注；标签不由博主昵称或简介推断。同输入版本已有验证分类时，执行服务可以复用并组装，研究 Builder 不必重新输出分类和兼容记录。调用方未提供已验证分类时，不能把旧规则标注当作完成结果。现有定义适合就复用，含义确实不同时可新增，一篇可有多个同轴或跨轴标签；证据不足可空，并说明未知。

当前接口支持 topic、format、commercial_signal 三轴；轴内类别开放。标签写明定义、依据与边界，避免同义标签膨胀。分类应帮助读者理解内容对象与所讨论的问题，不以“出现某关键词”替代语义判断。已深读的样本应结合其实际内容分类，不统一降回标题规则。不要让旧关键词初分限定新分类。标签表的 evidenceRefs 只能指向本次冻结 corpus 或批次中的 reconstruction（可带有效字段指针）；旧 annotations 仅供背景参考，不作为分类依据引用。不得照搬旧 annotations 的标签再替换引用来伪装自适配。

- 表层归属沿用接口枚举 surface_title：主题或商业信号只引用该帖自己的 `#/records/N/title` 或 `#/records/N/visibleText`。format 轴还可引用同一帖的 `#/records/N/mediaType`，但仅支持视频/图文等基础媒介类型，不能据此推断口播、剪辑或论证形式。
- 来自深度分析的归属标 deep_builder，引用该帖自己的 reconstruction。
- 分类覆盖本次冻结的全部已观察清单，不意味着覆盖博主历史全部作品。
- 标签重叠，各类占比不要求合计100%。说明分母、未分类数与证据层级。
- 融资、众筹、营收、销量是不同信号；标题出现数字，只能证明标题如此表述，不能证明金额或商业成效真实。

## 5. 来源、样本与可追溯性

调用方指定的实际清单和批次决定样本数，不把某次试跑的12篇或21篇写成所有任务的普遍前提。重叠分组中的同一帖子只分析一次，保留各分组归属。

每条深度观察必须引用该帖自己的、当前冻结版本的 reconstructionArtifactRef，优先定位具体字段。不得跨帖借证，不以表层详情代替深度依据。全部已构建深度样本在综合支持或反例中可追溯，不能只使用几个顺手的高赞样本。

保留事实层级：可见观察、作者主张、分析推断、未知。形式评估通过也不等于作者技术/商业主张得到外部验证。深度已验证与尚未验证分别使用接口规定的 deep_validated／deep_provisional，并保留警告；不可读媒体只支持 surface_only，不能写内部机制。

公开点赞不证明曝光、完播、转化、投放、销售。所有统计声明观察范围和分母，并明确已构建数、已验证数；零已验证时综合仍是待验证认识。主页总数与冻结清单可能时点或口径不同，未经核实不据其差值断言精确缺失数。预算截断的清单不能称全量。混合评估策略可一起研究内容，但不比较不同策略的通过率、警告数、修复次数或完整度分数。

若 batch item 包含 `researchReview`，逐篇读取其 `reviewStatus`、`candidateStatus`、意见和修订记录：`completed_no_findings` 只代表该原稿审阅未发现修改项，不代表真实世界效果已验证；`revised_unverified` 是已修订但未再次独立复核；`failed` / `review_incomplete` 是审阅执行未完成，不是正文错误。综合必须声明实际纳入的报告版本和这些边界，不能静默丢掉未复核样本后称完整，也不能继承旧版本通过状态。

修订后的单帖是新的事实源；媒体相对路径按照调用方提供的原始资源目录映射解析。旧综合和旧评估不是新版本事实源。保留输入版本，不借旧报告填空。

本轮任务若附带 Host 的阅读疑问，先在冻结材料中验证其前提，允许得出“问题已被回答”或“原假设不成立”。修订归到事实源所在层：单帖缺失交回单帖 Builder；跨帖关系或推断问题由综合 Builder 修订；原字段已有但页面不可达交回展示层。综合不得替这些层暗中补写。

## 6. 交回前自查

读者能否具体说出：这个博主讲了什么、哪些知识联系有用、模式有哪些例外、还有什么需要研究？每个答案能否追到具体帖子及当前证据？

完成后运行执行器提供的本次输出校验命令；研究草稿模式由程序组装固定字段后复用完整候选校验，整份候选模式直接使用 `validate-candidate.ts`。两者均应复用项目 Schema、逐帖分类引用和跨帖绑定检查，不能只通过 Schema 就宣布完成。对报错回查真实输入再修正，不通过替换成无依据引用来消除错误。指出仍未解决的输入或内容缺口。自查不写“独立验证通过”；后续复核与 Host 实际阅读是另外两步。
